# 수출신고필증 샘플 분석 및 초기 비교

로컬 샘플 40개 PDF, 165쪽을 대상으로 페이지별 텍스트 존재 여부를 확인했다. 89쪽에서 텍스트가 추출됐고 76쪽에는 추출 가능한 문자가 없었다. 대표 페이지에서 갑지, 을지, 복수 품목, 스캔, 도장·형광펜 표시, 목차, 송장, 항공화물운송장, 선하증권, 수출신고서를 확인했다. 문서 내용, 파일명, 원본 이미지나 신고값은 리포트에 기록하지 않았다. 로컬에서 수행한 집계만 사용했다. 개발 도구의 전체 처리·전송 경로가 오프라인이라는 점은 확인되지 않았다.

아래 수치는 텍스트가 있던 페이지 중 새 파서가 신고필증 제목을 확인한 80쪽을 동일하게 비교한 결과다. 실제 값 대조용 정답셋과 독립 검증셋을 만들지 않았으므로 정확일치율과 오인식률은 산출할 수 없다. 반복 페이지와 반복 품목이 포함될 수 있다.

| 항목 | 기존 정규식 | 신규 PDF 경로 |
| --- | ---: | ---: |
| 신고번호 후보 | 2 | 96 |
| 신고일자 후보 | 0 | 96 |
| 수리일자 후보 | 40 | 40 |
| 품목란 후보 | 0 | 96 |
| 세번부호 후보 | 0 | 82 |
| 품목별 USD FOB 후보 | 0 | 82 |
| 순중량 후보 | 0 | 82 |
| 화주 사업자등록번호 후보 | 0 | 40 |

파서 호출 시간 합계는 89쪽 기준 기존 약 0.04초, 신규 약 0.10초였다. 이 측정은 PDF 로드, OCR 프로세스, API, 화면 표시 시간과 분리한 단일 실행 측정이다. 샘플 2개 스캔 파일의 Windows OCR 경로를 시도했으며 Windows PowerShell 실행 정책으로 인식을 시작하지 못했다. 운영용 OCR 정확도 목표, 독립 검증, 회전·저해상도·정정 문서 정확도와 업로드부터 화면 표시까지 걸리는 시간은 미검증이다.

로컬에서 `python -m epms.ocr_audit "<샘플 폴더>"`를 실행하면 집계를 재현할 수 있다. `--private-manifest`를 지정하면 샘플 ID와 SHA-256, 페이지 크기·회전·문자 수 및 후보 필드별 위치를 지정된 로컬 JSON에 저장한다. 이번 실행은 Git 제외 경로인 `build/smart-ocr-sample-inventory.json`에 기록했다.
