# 종전 공동선별비 검토 정리

현재 업무는 **증빙·선별기록 → 물량 연결·계산 → 정산 결과**입니다. 사용법은 [공동선별비 정산](SETTLEMENT_WORKFLOW.md)을 따릅니다.

## 제품에서 제거한 작업

- 담당자 업무흐름, 다음 행동 안내, 전체 도구 메뉴
- 종전 시설·작업 중복 화면, Excel 대사, PDF 증빙 대사, 입고 CSV 화면
- 종전 신청 매칭·예약·검토·보완 상태 전환 화면
- 독립 정책 검토·모의계산·그룹 모의계산·검토 통계
- 종전 비용·거래·생산·비용 대사 화면
- 회원별 지급명세·지급 준비 대장·준비 종합 점검·서면 결재·지급 화면

사용 화면에서 참조되지 않던 TSX 22개, 전용 브라우저 시나리오 5개, 공통 메뉴 테스트 도구와 옛 메뉴 캡처 도구를 삭제했습니다. 새 정산의 브라우저 시나리오가 클릭·드래그·계산·PDF와 재열기를 검증합니다.

종전 작성 API를 호출하던 배포 스모크와 옛 추적 문서 생성 도구도 제거했습니다. 과거 인쇄 HTML 검증 도구는 역사 자료용임을 명시했습니다.

종전 API 등록 파일은 제품에서 제거했습니다. 새 `sorting_shared_api`는 시설 관리, 잔량 조회, 과거 조회·다운로드와 제한된 예약 해제만 제공합니다. 종료한 작성·심사·결재·지급 요청에는 HTTP 410과 새 메뉴 안내를 반환합니다.

## 유지한 것

원본 증빙, 선별기록, 비용 사건, 종전 배분, 지급 기록, 계약 검증, 원장 변경 이력과 DB 백업은 삭제하지 않았습니다. 새 정산이 사용하는 공용 잔량·중복 방지 함수도 유지합니다. 별도 DB 마이그레이션이나 운영 데이터 일괄 수정은 없습니다.

과거 출력·잠금·해제 검증에 필요한 도메인 코드는 유지합니다. 종전 작성 API는 **테스트 전용 fixture**로만 보관하여 과거 기록의 회귀 검증과 합성 데이터 구성에 사용합니다. 제품의 실행 경로에는 해당 fixture를 등록하는 설정이나 환경변수가 없습니다.

## 보관함에서 예약 정리

`공동선별비 정산` 첫 화면 또는 `정산 결과`의 **종전 공동선별 자료·예약 보관함**을 엽니다. 새 정산 작업을 만들지 않아도 조회할 수 있습니다.

1. 종전 자료의 활성 예약 물량과 배부 비용을 확인합니다.
2. **예약 상세 보기**에서 연결된 기록·신고 품목란과 비용을 확인합니다.
3. 잠금이 없는 자료는 사유를 입력하고 **종전 예약 해제·잔량 환원**을 누릅니다.
4. 선별·신고 양쪽 물량과 비용이 함께 환원되며 원본·배분 행·해제 이력은 보존됩니다.
5. 필요한 경우 확인된 기록을 새 정산에서 선택·보완하여 다시 연결합니다. 종전 신청을 검증 없이 자동 확정·전환하지 않습니다.

서면 상신·결재·지급 기록에 잠긴 건은 일반 예약 해제를 허용하지 않습니다. 보관함에서 잠금 사유와 서면 결과를 조회할 수 있습니다. 서면 원장 정정·환수 절차는 새 정산 기능에 포함하지 않았으며 기존 잠금을 임의 해제하지 않습니다.

해제 요청에는 원래 수정 차수가 필요하고 서버 쓰기 잠금 안에서 한 번에 처리합니다. 다른 조직 자료·오래된 요청·중복 해제로 잔량을 이중 환원하지 않습니다.

## 문서·테스트

`docs/sorting`의 기존 문서는 종전 설계 보관임을 상단에 표시했습니다. 새 안내와 충돌하는 옛 절차를 현재 사용법으로 취급하지 않습니다. 과거 서버 규칙 테스트는 테스트 전용 작성 fixture로 분리하고, 실제 제품에는 종전 작성 API가 없는지 별도로 검사합니다.

배포 EXE/ZIP에는 웹 빌드만으로 반영되지 않으므로 별도 패키징이 필요합니다.
