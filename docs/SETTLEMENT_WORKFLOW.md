# 공동선별비 정산

사무국 직원의 기본 흐름은 **증빙·선별기록 → 물량 연결·계산 → 정산 결과**입니다. 왼쪽 메뉴의 `공동선별비 정산`에서 작업합니다. 회원사 명부, 계약서 등록, 수출신고필증 등록, 회원사별 공동정산 수출실적의 기존 계산·확정 흐름은 유지합니다.

## 시작

1. 회원사·계약·공동선별장·수출신고 품목란을 기존 메뉴에서 준비합니다.
2. 공동선별비 정산에서 정산 제목, 사업연도, 선별장, 대상 기간을 지정하고 **작업 생성**을 누릅니다.
3. PDF 증빙을 등록하고 일별·월별 수출용 선별물량을 입력합니다. 내수·탈락·감모는 별도로 입력하며 모르는 값은 비워 둡니다.
4. 선별기록·증빙 등록에서는 PDF를 직접 보고 생산자·선별일(기간)·수출용 물량을 입력한 뒤 **PDF 확인·기록 저장**을 누릅니다. OCR과 항목별 근거 문구는 필수가 아닙니다. 미완성 자료는 임시 저장할 수 있으며, 등록할 때 빠진 항목을 필드별로 안내합니다.
5. 필요한 급여·지급 증빙은 **급여·비용**에서 비용 사건 하나에 모아 저장합니다.
6. **물량 연결·계산**에서 선별기록과 수출신고 품목란을 연결하고 가정값을 입력합니다.
7. **연결 확정·계산** 후 **결과 PDF 다운로드**를 누릅니다.

공동선별장 지정 증빙은 명부 화면에서 직접 PDF를 업로드하거나 기존 파일명으로 선택합니다. 품목은 통합조직 품목으로 고정하며 내부 자료 번호를 입력하지 않습니다.

## 원본·OCR

- 증빙 PDF는 파일당 20MB, 1~150쪽까지 지원합니다.
- `이 페이지 OCR`은 PDF 텍스트를 우선 사용하고, 텍스트 없는 스캔 페이지는 기존 Windows 로컬 OCR을 사용합니다. 외부 서비스로 전송하지 않습니다.
- 수출신고필증 전용 추출 양식을 선별일지에 적용하지 않습니다. 선별물량·내수·탈락·총량·급여·작업일 라벨의 후보를 원문과 함께 표시합니다.
- 자유 양식·복잡한 표·손글씨에서는 후보가 없거나 틀릴 수 있습니다. 수동 입력과 원문 대조가 필요합니다. 후보를 자동 확정하거나 기존 입력값을 덮어쓰지 않습니다.
- 처리 이력은 페이지별로 보존되며, 다음 페이지나 실패한 페이지를 선택해서 재처리할 수 있습니다.
- 동일 PDF는 해시로 재사용하지만 동일 거래인지까지 자동 판정하지는 않습니다.

## 선별장 명부·숫자 입력·이월 매칭

공동선별장 명부는 목록에서 검색하고 신규 등록·상세 수정을 선택합니다. 지정 종료일은 선택이며, 미입력은 종료일 미정으로 보관합니다. 시작일·지정 증빙은 계속 필요합니다.

금액·중량은 입력 중 천 단위 쉼표를 표시합니다. 소수와 원래 정밀도를 유지하며 저장·계산에는 쉼표 없는 값을 사용합니다. 빈칸은 미확인이고 0은 명시적인 0입니다.

선별월과 신고·선적월은 달라도 됩니다. 다음 달 또는 다음 해 선적도 연결할 수 있습니다. 후보의 선적일은 반드시 있어야 하며 선별 시작일보다 이전이면 연결 확정할 수 없습니다. 사유로 날짜 역전을 허용하지 않습니다. 선별 기간 필터는 다음 달의 신고 후보를 숨기지 않습니다. 월별 기록은 시작일을 날짜 비교 기준으로 사용하므로 실제 날짜별 귀속이 필요하면 원문에 따라 일별 기록으로 나눕니다.

## 일별·월별·생산자 분할

선별기록마다 원본 기록번호·구분명을 사용합니다. 같은 기록을 보완할 때는 새 기록을 만들지 말고 기존 기록을 엽니다.

여러 생산자가 섞인 월별 문서는 생산자를 미확인으로 두어 원집계로 등록할 수 있습니다. 확인된 생산자별·일별 기록을 추가할 때 **원집계 기록**을 선택합니다. 원집계와 그 분할 기록은 공통 물량 한도를 사용하므로 여러 정산에서 사용하더라도 원집계 총량을 넘을 수 없습니다.

독립된 작업이지만 생산자·기간이 겹치는 경우, 원문에 근거한 별개 물량의 구분 사유를 입력합니다. 일별 기록과 월별 누계를 별개 실적으로 중복 사용하면 안 됩니다. 원집계 연결은 저장 후 바꾸지 않습니다.

## 선 연결과 잔량

- 왼쪽 카드를 선택하고 오른쪽 카드를 선택하거나 연결점에서 드래그합니다. 키보드 Enter/Space 선택도 지원합니다.
- 기본 연결량은 양쪽 현재 잔량 중 작은 값입니다.
- 한 기록을 여러 품목란에 연결하거나 여러 기록을 한 품목란에 연결할 수 있습니다.
- 카드에 마우스를 올리면 관계된 상대 카드와 선이 강조됩니다. 선 또는 연결 조정을 누르면 양쪽 사용량과 사유를 수정합니다.
- 검색·생산자·자료 기간·잔량 필터, 확대·축소·화면 맞춤과 연결 표를 제공합니다.
- 초안 연결은 새 물량을 예약하지 않습니다. 확정 시 다른 정산과 종전 검토 예약·출고가 사용한 물량도 서버에서 다시 확인합니다.
- 저장한 작업을 다시 선택하면 초안을 이어서 작업할 수 있습니다. 확정 작업을 수정·초안 저장하더라도 기존 확정 물량은 다시 확정하거나 해제하기 전까지 유지됩니다.

### 중량이 다를 때

예를 들어 선별 1,000kg과 신고 980kg을 980kg씩 연결하면 선별 잔량 20kg이 남습니다. 이 잔량은 다른 신고에 사용할 수 있습니다.

20kg을 계근·감모 등 차이로 종결하려면 선별 측 사용량 1,000kg, 신고 측 사용량 980kg을 입력하고 사유를 남깁니다. 이 경우 선별 측 1,000kg을 소진하므로 20kg을 다시 사용할 수 없습니다. 원본 수치는 바뀌지 않습니다.

- 허용 절대 차이와 차이율을 직접 지정합니다. 차이율의 분모는 해당 연결의 **신고 측 배분량**입니다.
- 두 기준이 있을 때 `둘 다` 또는 `하나 이상`을 선택합니다. 기준이 없으면 일치하는 중량만 일반 통과합니다.
- 기준 밖 차이도 추가 확인 사유와 실제 근거 PDF 페이지를 지정하면 참고 계산으로 확정할 수 있습니다.
- 원본 초과·음수·잘못된 날짜·근거 페이지 오류는 사유 입력으로 우회하지 못합니다.

## 계약과 신고 검증

기존 제조자·회원사·역할·사업자번호·신고 유효 상태 검사와 계약 검사를 적용합니다. 제조자와 화주 또는 대행사 중 한 회원사와 유효 계약이 있으면 통과하며 동일 사업자의 자기 계약은 생략합니다.

신고 제조자와 선별기록의 실제 생산자가 같아야 합니다. 시설 운영자를 생산자로 추정하지 않습니다. 해당 수출연도 정책이 있으면 대상 HS코드와 회원자격 기준도 적용합니다. 정책이 없으면 기본 검사만 적용했다는 참고 계산 안내를 남깁니다.

정산 기간 밖 작업, 다른 연도 수출, 선별 이전 수출 등은 귀속 확인 사유를 요구합니다. 원본 날짜를 바꾸거나 실제 출고를 자동으로 증명하지 않습니다.

## 비용 사건과 배부

같은 급여대장·이체증·확인서를 하나의 비용 사건에 첨부합니다. 파일별 금액을 합산하지 않습니다. 사건 구분명과 지급 거래 구분명을 통해 중복 등록을 차단합니다.

발생액, 분할 지급, 환입·지급 취소, 제외액·사유를 기록합니다. 미지급액은 지급 비용에 포함하지 않습니다. 한 이체를 여러 작업에 배분해야 하면 하나의 비용 사건에 관련 작업을 모두 연결합니다.

연결 화면에서 비용을 선택하고 다음 중 하나를 사용합니다.

- 직접 확인액
- 작업시간 비율: 확인된 수출 작업시간 / 전체 작업시간
- 물량 비율: 확인된 수출분 물량 / 전체 물량
- 수동 배부액: 원문에 근거한 금액

비율 배부는 `순지급액 − 제외액`에 적용하며 소수점 6자리에서 내림 처리합니다. 다른 정산·종전 검토 배부까지 합쳐 지급 비용 잔액보다 초과 배부할 수 없습니다. 선이 늘어나도 같은 비용을 반복 합산하지 않습니다.

다른 사업의 지원이 확인된 경우 물량 한도·금액 한도·차감액에 근거를 입력할 수 있습니다. 종전 패키지 양식이라는 사실만으로 중복 지원이라고 판단하지 않습니다. 외부 지원 이력을 자동 조회하지 않습니다.

## 현재 계산 기준

공식 기준이 미정이라는 사용자 확인에 따라 **가정값에 따른 참고 계산**만 제공합니다. 가정값을 확인하고 입력해야 확정할 수 있습니다. 미입력 필수값은 0원으로 추정하지 않습니다.

1. 연결별 `min(선별 측 사용량, 신고 측 사용량)`을 합산하여 인정물량을 구합니다. 연결 간 차이를 임의로 상쇄하지 않습니다.
2. 이번 작업 물량 한도가 있으면 인정물량에 먼저 적용합니다.
3. 물량 단가 방식의 기준액은 `적용물량 × 단가`입니다.
4. 실비 한도 방식의 기준액은 `min(적용물량 × 단가, 배부한 지급 비용)`입니다.
5. 단가에 보조율이 포함되어 있지 않으면 기준액에 입력 보조율을 곱합니다. 포함된 단가이면 다시 곱하지 않습니다.
6. 작업 금액 한도, 다른 지원 등 차감액, 선택한 원 단위 절사·반올림을 적용합니다.
7. 시설·사업연도 누적 금액 한도가 있으면 다른 활성 확정 작업의 사용액을 제외한 잔액으로 제한합니다. 누적 한도 잔액은 원 미만 절사합니다.

단가, 보조율, 한도, 허용 차이는 임의 기본값이 없습니다. 배부 비용을 비교하는 순서 등은 위 참고 산식을 따르며 향후 실제 사업 기준이 달라지면 정책과 산식의 추가 검토가 필요합니다.

## 확정·수정·PDF·백업

확정은 사무국의 입력·연결·참고 계산 저장입니다. 외부 승인·은행 지급 완료가 아닙니다.

- 서버 쓰기 잠금과 원본 수정 차수 검사 후 양쪽 물량·비용을 한 거래로 저장합니다.
- 같은 확정 요청 재시도는 동일 결과를 반환하며 이중 차감하지 않습니다.
- 원본 변경·계약 변경·비용 환입은 새 계산에서 다시 검증합니다. 과거 결과와 PDF는 바뀌지 않습니다.
- 확정 해제는 현재 물량과 비용만 환원하며 과거 PDF는 보존합니다.
- 결과 PDF는 확정 시 생성한 실제 파일입니다. 한글 글꼴은 Windows의 Malgun Gothic을 포함해 생성합니다. 작업자별 급여·계좌 같은 불필요한 상세는 결과 PDF에 넣지 않습니다.
- 기존 데이터베이스 백업에 증빙, 신규 배분, 비용, 확정 스냅샷과 PDF가 포함됩니다.

마이그레이션 `0006`은 작업·양쪽 중량 연결·비용 연결·확정 스냅샷 테이블을 추가합니다. 원본은 기존 선별·증빙·비용 테이블을 재사용합니다. 종전 메뉴는 일반 화면에서 숨기고 종전 검토 Excel은 결과 탭의 보관함에서 열 수 있습니다.

## 개발 실행과 검증

### 독립 선별기록·증빙 접수 (마이그레이션 0007)

`선별기록·증빙 등록`에서 정산 작업 생성 없이 선별장·대상 기간별 자료를 접수합니다. `공동선별장 명부`는 시설 기본정보를, `공동선별비 정산`은 등록 자료의 연결·배부·참고 계산을 담당합니다.

- 접수 묶음에는 접수일, 일별/월별 대상 기간, 최초/추가/정정 구분, 이전 접수, 보완 요청·메모·PDF 문서 관계를 기록합니다. PDF 여러 개 접수·기존 파일 재사용·정정본과 이전 PDF 지정이 가능합니다. 원본 해시와 페이지 수는 기존 PDF 저장소를 사용합니다.
- 선별물량은 여러 행으로 입력합니다. 앞 행의 날짜·생산자는 복사하지만 물량은 복사하지 않습니다. 공란은 미확인, `0`은 실제 수출 없음입니다. 원문·생산자·물량·기간·근거 확인이 끝난 양수 수출 물량만 새 정산 후보가 됩니다. 접수 묶음의 보완 요청 중에는 해당 물량·비용을 확정하지 못합니다.
- PDF 원문과 입력값을 나란히 봅니다. 페이지별 또는 선택 범위 순차 로컬 OCR을 실행하며 처리 중지는 다음 페이지부터 적용됩니다. 사용자가 선택한 후보만 입력 행이나 급여 발생액에 적용합니다. 모호한 값·날짜·단위는 추정하지 않으며 수동 입력 가능합니다. 후보 적용은 원문 확인을 해제하고 항목별 근거 페이지를 보존합니다.
- 월 원집계와 일별/생산자 상세는 기존 `parent_id` 공유 물량을 사용합니다. 접수 합계와 연결 화면의 전체 물량·잔량에서도 같은 공유 풀을 중복 합산하지 않습니다. 내수·탈락·수출 0kg 기록은 보관하지만 수출 연결 후보로 새로 표시하지 않습니다.
- 비용은 발생·지급·환입·제외액과 관련 선별기록을 같은 비용 사건에 모읍니다. 파일 추가만으로 비용을 늘리지 않습니다. 실제 지급액·배부액·참고 지원액은 구분합니다.
- 종전 기록은 `기존 기록 연결`로 같은 ID를 접수 묶음에 연결합니다. 정정 제출도 기존 기록을 연결해 변경 사유와 새 수정 차수로 수정합니다. 이전 접수에서도 기록과 변경 이력을 조회할 수 있으며 최신 정정 접수 외의 원 접수에서는 선별기록을 조회 전용으로 표시합니다.
- 사용 중인 기록을 수정하면 해당 정산 목록과 재대조 안내를 제공합니다. 기존 연결·확정 PDF를 자동 삭제하거나 덮어쓰지 않습니다. 새 확정 시 원본 수정 차수를 다시 확인합니다.
- `sorting_receipts` 테이블만 추가하며 기존 시설·PDF·선별·비용·정산 ID를 재생성하지 않습니다. 기존 백업 API에 접수 묶음과 PDF가 함께 포함됩니다. 운영 데이터에 예시 자료를 넣지 않습니다.

### 물량 연결 작업 공간

- 작업 대상 기간을 기본 조회 기간으로 적용합니다. 왼쪽은 현재 공동선별장 기록을 생산자·날짜순으로 정렬합니다.
- 기본 `관련 후보`는 사업자등록번호로 생산자가 일치하고, 조회 기간·양수 잔량·현재 신고/계약 검증을 통과한 신고입니다. 선별기록을 고르면 해당 생산자로 좁힙니다. 이름 유사도나 날짜 간격만으로 연결하지 않습니다. 날짜 차이는 정렬 참고이며 별도 적격 기준이 아닙니다.
- `전체 신고 보기`로 확인 필요 자료도 조회할 수 있습니다. 기존에 연결한 신고는 관련 후보 모드에서 필터와 관계없이 남겨 관계가 사라지지 않게 하며, 모든 연결은 숨겨져도 잔량 계산에 포함됩니다.
- 파란 선·점은 양쪽 잔량이 0인 일치 연결, 주황은 잔량 있는 일치 연결, 빨간 점선은 물량 차이·초과·입력 확인입니다. 사유를 설명한 차이도 원본 차이를 숨기지 않습니다. 실제 확정 가능 여부는 기존 서버 검증을 따릅니다.
- 카드를 선택하면 상세 정보를, 선을 선택하면 오른쪽 패널에서 양쪽 물량·차이 사유·근거를 수정합니다. 좁은 화면에서는 패널이 닫을 수 있는 옆 서랍으로 표시됩니다. 선별 PDF는 키보드로 닫을 수 있는 원문 대조창으로 엽니다.
- 드래그·클릭·키보드 연결을 지원하며 양쪽 잔량 중 작은 값을 제안합니다. 생산자 식별 불일치·잔량 없음은 연결 단계에서 안내합니다. 자동 연결하지 않습니다.
- 연결 해제 직후 `직전 연결 변경 취소`가 가능합니다. 비용과 계산 기준은 필요할 때 펼칩니다. 고정 하단에는 참고 지원액·저장 상태·확정 버튼이 표시됩니다. 확정 이력과 다른 초안은 별도 문구로 표시하고 과거 PDF는 유지합니다.
- 이번 변경은 화면·후보 탐색 개선이며 데이터베이스 마이그레이션, 지원액 산식, 회원사별 수출실적 규칙을 변경하지 않습니다.

- 웹 빌드: `npm run build`
- 새 테스트 DB로 실행: `./run.ps1 -Preview -Database build/settlement-preview.db -Port 18790` (공동선별 기능을 사용하려면 실행 전 `EPMS_SORTING_ENABLED=1` 설정)
- 서버: 프로젝트 의존성이 있는 Python에서 `python -m pytest tests -q`
- 브라우저: 전용 빈 DB 서버를 지정하여 `EPMS_TEST_URL`, `EPMS_SETTLEMENT_E2E=1` 설정 후 `npx playwright test tests/browser/settlement.spec.ts --workers=1`

브라우저 테스트는 기존 조직이 있는 DB에서 예시 데이터 등록을 거부합니다. 운영 DB를 테스트 대상으로 지정하지 마세요.

소스·웹 빌드는 기존 배포 EXE/ZIP을 자동으로 바꾸지 않습니다. 배포본에는 `reportlab` 의존성과 새 마이그레이션을 포함해 별도 패키징해야 합니다.

## 종전 작업 정리와 보관함

종전 작업 화면과 작성·결재·지급 API는 종료되었습니다. 첫 화면과 결과 탭의 **종전 공동선별 자료·예약 보관함**에서 원본·예약 내역·검토 Excel·서면 결과를 조회할 수 있습니다. 잠금 없는 활성 예약은 사유와 수정 차수를 확인한 뒤 물량·비용을 함께 해제할 수 있습니다. 서면자료에 잠긴 건은 해제하지 않습니다. 자세한 범위는 [종전 검토 정리](SORTING_CLEANUP.md)를 참조하세요.
