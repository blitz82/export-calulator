# PHASE 5 하이브리드 OCR

전자 PDF 텍스트와 좌표를 먼저 읽는다. 문자가 없거나 주요 필드가 비면 Windows OCR을 시도한다. 수리일자, 선적일자, 대행자·제조자 등록번호도 해당 라벨이 있고 값이 없으면 보완 대상이 된다. 텍스트에서 신고필증을 식별하지 못했지만 단일 이미지가 표시 영역의 절반 이상을 덮는 PDF도 보완 대상이다. OCR에서 신고필증을 식별하지 못하면 기존 텍스트는 검토용으로 유지한다.

PDF 페이지에 명시된 회전을 적용하기 전의 방향으로 OCR용 이미지를 렌더링하고 좌표를 원본 미리보기 방향으로 다시 변환한다. 스캔에서 일반 인식 호출은 성공했으나 후보를 찾지 못하면 같은 해상도의 회색조 대비 이미지로 한 번 다시 시도한다. Windows OCR 호출 실패 시 사용자에게 안내한다. Windows 스크립트는 원본 크기, 각도, 전체 인식 문자열, 줄·단어 순서와 단어 사각형을 반환한다.

PDF와 OCR 후보는 페이지 안에서 신고번호와 품목란이 일치할 때 병합한다. 두 소스에 한 행씩 있고 공유 식별자 하나가 일치하며 다른 식별자 값이 충돌하지 않는 경우에도 누락을 보완할 수 있다. 신고번호의 공백·하이픈·대소문자는 비교용으로 정규화한다. 품목란 번호의 선행 0은 보존한다. 금액·중량은 기존 Decimal 규칙, 날짜는 기존 날짜 규칙으로 같은 값을 비교한다. 서로 다른 값은 PDF 후보와 OCR 대체 후보의 개별 근거를 기록한다.

후보에는 원문, 정규화 문자열, 추출 방식, 상태와 확인 가능한 사각형을 기록한다. 페이지에는 적용 템플릿이 기록된다. 유효하지 않은 날짜나 금액은 자동입력 후보에서 제외하며, 판독되지 않은 식별자에 추측한 문자를 넣지 않는다. 자동입력 후보와 충돌은 원본 검토 단계에서 표시된다.

## 검증과 남은 범위

- 모의 OCR 응답으로 전자 PDF 우선 경로, 누락 보완, 중복 표기 비교, 실제 후보 충돌, 회전된 이미지의 좌표 변환, 대비 재시도 및 비정상 응답 차단을 시험했다.
- 합성 혼합 PDF로 실제 래스터 면적 판정을 시험했다. 초기 Windows PowerShell 정책은 `Restricted`였다. 스크립트 구문 검사와 호출 실패 시 전자 텍스트 보존 및 사용자 안내를 확인했다.
- PDF 샘플 40개·165쪽의 전자 PDF 비교에서 주요 후보 건수는 이전과 같았다. 선적일자와 대행자·제조자 등록번호는 명시 라벨을 처리하지만, 이 샘플 집계에서는 해당 후보를 확보하지 못했다.

전자 PDF의 누락 필드 보완은 페이지 OCR 후 일치한 필드만 반영한다. 필드별 자동 영역 OCR, 실제 스캔 인식률과 기울기 보정, 목적국·품명·수량·총계·정정정보의 전체 매핑, 담당자의 필드별 확인 이력 영속화는 남아 있다. invoice2data 연동은 [PHASE 3 기술 실증](INVOICE2DATA_INTEGRATION.md)의 제약을 따른다.

## Windows OCR 재검증

임시 Windows PowerShell 세션에 `RemoteSigned`를 적용하고 해당 세션에서 EPMS 추출 코드를 실행했다. 실제 스캔 PDF 3개, 6쪽 모두에서 Windows OCR 텍스트를 받았다. 신고필증 4쪽 중 2쪽에서 서식과 필드 후보를 얻었다. 한 쪽은 신고번호와 수출화주 상호, 다른 쪽은 HS코드가 나왔다. 세 후보의 근거 좌표도 확인했다. 나머지 신고필증 2쪽은 OCR 텍스트를 받았으나 서식 식별에서 누락됐다. 혼재한 항공화물운송장과 송장 2쪽은 신고필증 후보를 생성하지 않았다. 이 표본에서 품목란 번호, 순중량, FOB의 자동입력은 확인되지 않았다.

### 스캔 매핑 수정 후 재검증

실패한 페이지의 OCR 단어를 대조한 결과, 일부 제목은 인식됐으나 출력 순서에서 상단 제목으로 처리되지 않았다. 품목 표의 세번부호, 순중량, 신고가격도 다른 문자열 행으로 들어왔고 일부 OCR 결과의 FOB 표기가 깨졌다. 단어 좌표로 줄 읽기 순서를 다시 구성하고, 세 가지 품목 라벨이 같은 높이에서 확인될 때 값들을 연결했다. 총계 행과 혼동하지 않도록 이 세 라벨이 함께 나타나는 경우에만 품목 추출을 보완했다. 한 페이지에서 품목 후보가 하나로 좁혀지면, 빠진 번호 또는 값의 영역을 대비 개선 후 확대해 다시 읽었다. 후보가 충돌하거나 형식 검증을 통과하지 못하면 공란을 유지했다.

| 항목 | 기존 표본 수정 전 | 기존 표본 수정 후 | 수정에 사용하지 않은 별도 스캔 |
| --- | ---: | ---: | ---: |
| 신고필증 페이지 식별 | 2/4 | 4/4 | 3/3 |
| 첨부 서류 제외 | 2/2 | 2/2 | 해당 표본 없음 |
| 품목란 번호가 나온 페이지 | 0 | 2 | 1 |
| 순중량이 나온 페이지 | 0 | 3 | 3 |
| 품목 FOB가 나온 페이지 | 0 | 3 | 3 |

페이지별 후보 유무 집계이며 갑지·을지에 반복된 값이 포함될 수 있다. 합성 시험에서는 좌표로 분리된 라벨과 값 연결, 전체 합계 제외, 선행 0 보존 및 잘라낸 이미지 좌표의 원본 변환을 확인했다. 실제 스캔 후보 중 동일 신고번호의 전자 PDF로 필드 값을 교차 확인한 사례는 없었다. 독립 수기 정답셋이 없어 실제 후보의 정확일치율은 아직 계산할 수 없다. 일부 페이지의 번호·HS코드는 확대 후에도 남은 공란이 있다. 전체 Python 회귀시험은 74건 통과했다.
