# 회원별 귀속 원장·지급명세 검토 사용법

2026-11-23 최신 보완: 검토 명세 이후 서면 상신본, 외부 결재액, 외부 지급 결과/잔액 명세를 추가했다. 검토 참고액과 외부 결재액은 구분한다. 상세는 [PAPER_WORKFLOW.md](PAPER_WORKFLOW.md), 최신 검증은 IMPLEMENTATION_STATUS.md를 따른다.

명세 보존 이후의 수동 준비액·예정일·준비 상태 기록은 [지급 준비 검토 대장](PAYMENT_PREPARATION.md)에서 제공한다. 운영 승인이나 실제 지급확정 단계는 아니다.

2026-11-23. 지급명세 설계의 1~2단계 중 검토 전용 귀속·명세 기능을 구현했다. 지원대상/수령 주체·귀속/환류·산식·한도·절사 등의 정책, 독립 인증/직무분리, 운영 승인·보조금 지급·회수 원장은 미구축/미확정이다. 이번 화면은 공식 지급명세나 실제 지급확정 기능이 아니다. 실제 지급결과 확정 버튼을 켜지 않는다.

## 업무 순서

1. 기존 수출 매칭·예약에서 신고 품목란과 선별 작업/출고를 연결한다. 1개 작업→복수 신고, 1개 신고란←복수 작업/시설, 복수 신고↔복수 시설 모두 배분행으로 구분한다.
2. 상단 ‘검토할 신청’을 선택하고 ‘검토자료 보관 → 회원별 지급명세’를 연다. 현재 범위는 선택한 신청이며 여러 신청의 지급을 합산 확정하는 기능은 아니다.
3. ‘회원 귀속행 추가’에서 신고·시설 배분행, 수혜 회원, 실제 귀속 kg, 증빙 ID, 원물/LOT 참조, 판단 근거를 입력한다. 같은 배분행·회원의 여러 원물 근거는 한 행으로 합쳐 증빙/판단 근거에 기록한다. 회원 등록은 지원 자격 승인이나 원물 생산자 동일성 인증이 아니다. 입고 비율 또는 직접·간접실적 비율로 자동 배분하지 않는다.
4. 비용은 기존 비용 원본·정상 이체 기록과 신청별 비용 배부를 먼저 등록한 뒤 해당 귀속행에 연결한다. 한 행에 여러 비용을 연결할 수 있다. 시설 불일치, 신청별 배부액 초과, 전체 활성 비용 배부의 정상 이체 후보 한도 초과, 비용/증빙 변경은 거절한다. 비용 귀속월과 선별월이 다르면 정책·근거 확인 사항으로 표시한다. 은행 실대사나 최종 비용 적격 판정은 아니다.
5. 수동 참고 지원액은 선택 입력이다. 정책/산식으로 자동 산출·심사된 금액이 아니며 승인액/지급액으로 전환하지 않는다. 공란은 미확인, 입력한 0은 수동 참고값 0이다. 비용 연결이 없으면 비용 금액도 미확인으로 유지한다.
6. 사유를 입력하고 ‘회원 귀속 검토 저장’을 누른다. 아래 편집 목록 전체를 새 버전으로 저장한다. 기존 기록을 수정할 때는 먼저 ‘현재 귀속 원장 불러와 편집’을 사용한다. 행을 모두 삭제한 뒤 저장하면 기존 귀속을 해제하는 새 검토 버전이 생긴다. 이전 이력과 신고 물량 예약은 삭제/해제하지 않는다. 탭 간 이동은 편집 목록을 유지하지만 새로고침·신청 변경은 저장되지 않은 편집을 보존하지 않는다.
7. ‘저장된 귀속으로 명세 검토본 보존’을 누른다. 미저장 편집, 원본 변경, 철회/반려, 빈 귀속 상태에서는 보존할 수 없다. 일부 물량/비용만 귀속된 검토본은 가능하며 사무국 전체본에 미귀속 내역을 표시한다. 완전 심사·승인을 뜻하지 않는다.
8. 보존된 명세를 선택해 ‘사무국 전체 검토본’ 또는 ‘○○ 회원 전용 검토본’을 고른다. Excel 및 인쇄/PDF 저장 미리보기를 제공한다. 회원 전용본은 해당 회원의 행·소계·비용 근거·해당 행 보완만 포함하며 다른 회원 및 전체 잔량/비용 pool 내역을 제외한다. 현재 세션은 사무국 로컬 권한이며 회원 직접 로그인 포털이 아니다.

## 명세 내용

- 기본 명세: 실제 신고번호·품목란·버전, 시설/선별일, 작업·출고 참조, 수혜 회원, 귀속량, 비용 귀속 검토액, 수동 참고액, 귀속 증빙·LOT·판단 근거.
- 승인액·실제 지급액: 항상 미확정(null). 과거 선별비용 이체 이력을 회원 보조금 지급으로 사용하지 않는다.
- 집계: 선택 대상 합계 및 회원별·시설별·신고 품목란/버전별 소계. 동명 회원/시설도 식별키로 구분한다. 미확인 비용/참고액을 포함한 금액 합계는 미확인으로 남긴다.
- 비용 근거: 비용별 배부액·귀속월·증빙 ID. 사무국 전체본은 미귀속 물량과 비용을 표시한다.
- 보완/보류: 저장 당시 신청 검토 응답과 귀속월 불일치를 함께 표시한다. 실제 수출이행·사무국 발급 확인서·외부 중복원장·정책/운영 통제는 별도 검토 대상이다.

예를 들어 D1에 시설 A 400kg+시설 B 600kg, D2에 같은 시설 A 작업 300kg을 연결한 경우 D1 1,000kg, D2 300kg, A 작업 700kg, B 작업 600kg, 전체 1,300kg으로 출력한다. 작업 원량을 신고마다 반복 합산하지 않는다. 수혜자별 귀속 합계는 각 배분행의 예약량 이하여야 한다. 여러 수혜자로 나눠도 동일 배분행의 한도가 늘지 않는다.

## 보존·변경·중복 통제 범위

귀속 원장은 기존 sorting_records의 BENEFICIARY_REVIEW, 명세는 BENEFICIARY_STATEMENT 종류로 append-only 보존한다. 별도 테이블/의존성/schema migration 없이 기존 기록 구조를 사용한다. 요청키 재전송은 같은 결과를 반환하며 내용이 다르면 거절한다. 신청 revision과 BEGIN IMMEDIATE를 함께 검사하여 동시 저장을 통제한다. 여러 귀속행이 부분 저장되지 않도록 전체 transaction으로 처리한다.

신청·신고·작업·시설·계약/정책·현재 예약 pool·회원·파일 해시·비용 및 전체 관련 비용 배부가 변경되면 귀속 원장을 재검토해야 한다. 검토 명세는 저장 당시 고정된 원문이며 나중의 변경·철회로 덮어쓰지 않는다. 일반 검토본에도 귀속 원장과 관련 회원/증빙을 포함한다. 원물/LOT 참조 및 근거는 로컬 검토기록이고 실물 추적·발급자 인증을 자동 보증하지 않는다. 로컬 관리자가 원본과 해시를 함께 바꾸는 공격까지 방지하는 전자서명은 아니다.

이 기능은 기존 물량/비용 예약 통제 위에서 **검토 귀속의 초과·중복 입력**을 막는다. 지급완료 물량 소비, 실제 보조금 지급의 중복 확정, 다른 PC/DB/타 사업의 전역 중복 지원을 막는 운영 원장을 구현한 것은 아니다. 기지급 자료를 가져와도 신규 보조금 지급 상태로 자동 승격하지 않는다.

## 남은 구현과 선행조건

정책상 수혜자·혼합 LOT 귀속·지원 산식·한도·절사·환류·중복 범위 및 기관 사용자/결재권한이 확정되면 승인 불변본 → 지급 준비 시 물량/비용 점유 → 보조금 전용 거래/회차 → 실제 지급결과 확정 → 부분 지급·실패/재이체·정정/환수 순으로 개발·인수한다. 지급 후 일반 철회로 물량이 재사용되는 경로는 허용하면 안 된다. 현 단계에서는 관련 운영 endpoint/official 출력의 기존 403 차단을 유지한다.

설계 상세는 [지급명세·지급확정 설계 검토서](PAYMENT_STATEMENT_DESIGN_REVIEW.md)를 참조한다. 기존 회원별 직접·간접실적의 계산/저장/제출/OCR 기능은 변경하지 않는다.
