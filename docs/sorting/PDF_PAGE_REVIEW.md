# PDF 페이지 검토·Excel 후보 대사 (2026-11-23)

`PDF 증빙 대사`에서 PDF를 올리고 `다음 미처리 쪽 추출`을 누른다. 최대 150쪽이며 한 번에 한 쪽씩 저장되어 같은 원본을 다시 올리면 이어서 처리할 수 있다. 원본 이미지와 순중량 후보를 대조하고 사유를 입력하여 로컬 대조 또는 보완 필요 기록을 저장한다. 추출 경고가 있으면 환경 복구 후 `현재 쪽 다시 추출`을 사용한다. 처리 쪽 수는 인식 성공·사람 대조 완료 쪽 수가 아니다.

재추출로 결과 해시가 바뀌면 기존 기록은 재검토 필요가 된다. 별도 Excel을 올리고 시트를 선택하면 신고번호 후보별 중량 차이를 비교한다. 번호 끝 검증문자 누락은 후보 검색에만 허용한다. 복수 후보·품목란 미확인·미인식은 자동 연결하지 않으며 반복 페이지 중량을 합산하지 않는다. 빈값을 0으로 바꾸지 않는다. 로컬 대조와 표의 일치는 실제 수출·신고 진위·정책 적격·지급 승인을 뜻하지 않는다.

API 경로는 pdf-status, pdf-process, pdf-image, pdf-page-review, pdf-excel-preview이다. 기존 세션·기능 OFF·조직 범위를 검사한다. 원본 SHA256과 추출기 버전/결과 해시를 검증하고 페이지별 후보를 내부 기록에 보존한다. 일반 records 조회에서는 OCR 내부 캐시를 제외한다. 대조는 원본/추출 해시·작성자·시각·사유를 append-only로 기록하며 재추출 변경 시 STALE_REVIEW로 표시한다. API는 요청당 최대 5쪽, UI는 1쪽씩 처리한다. 비용·신청·예약은 생성하지 않는다.

## 실제 자료 실행 범위

실제 스캔 PDF 4쪽에서 모두 Windows OCR 사용 불가 경고와 후보 0행을 확인했다. 별도 합성 이미지 진단에서 Windows PowerShell 스크립트 실행 제한을 확인했다. 연속 3회 환경 실패 시 로컬 도구가 종료 코드 2로 중단한다. 실행 정책·그룹 정책·언어팩은 변경하지 않았고 클라우드로 전송하지 않았다. 실제 301개 고유 PDF 쪽의 전수 OCR·사람 대조는 미완료이다. 민감한 페이지별 결과는 output/sorting-private/pdf-page-audit에만 보관한다.

합성 3170.4kg PDF 후보와 3170kg Excel 행의 0.4kg 차이 검출은 기술 시험이다. 제공 실제 신고 원본에서 그 차이를 검증한 결과가 아니다.

## 기술 시험

Python 전체 170 PASS(71.60초), 최종 오류 처리 보완 후 PDF 시험 4 PASS(2.56초), 프런트엔드 11 PASS, TypeScript/Vite build PASS. Edge 검토 흐름 3 PASS(7.0초): PDF 업로드·페이지 추출·원본 이미지·로컬 대조 기록, 기존 자료 대사/CSV, 예약/증빙/부분 반려/검토 출력이다. 페이지 재사용·재추출 후 stale 검토 거절·타 조직 차단·원본 변조·잘못된 PDF·범위 제한·읽기 전용 비교·반복 페이지 비합산을 시험했다. OCR 경고 0개를 성공 조건으로 가정한 최초 브라우저 시험은 실패했고, 경고의 명시적 표시를 허용하도록 검증 조건을 수정한 뒤 통과했다.

기존 OCR 엔진과 보호된 원장은 변경하지 않았다. 새 페이지 어댑터를 추가한 것이다. 정책 승인·기관 원본 대조·기업 PC 환경 및 네이티브 창 인수는 남아 있으며 M1 전체 완료가 아니다.

기능 OFF 기존 업무 Edge 9 PASS(21.0초), 최신 Lite exe 별도 합성 DB의 검토 Edge 3 PASS(6.9초)도 확인했다. 로그는 output/sorting-tests/pdf-stage-*.log이며 민감한 실제 원본 행은 포함하지 않는다. Lite 검증 ZIP의 SBOM/고지/마이그레이션/빌드정보 검사도 통과했다. 패키지 실행 시험은 headless 서버·브라우저 범위이며 네이티브 창 인수와 구분한다.
