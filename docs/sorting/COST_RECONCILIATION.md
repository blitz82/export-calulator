# 비용·이체·배부 대사 (2026-11-23)

마스터 M2 비용 원장의 검토 화면을 보완했다. 신규 송금·보조금 지급 확정 또는 실제 은행 대사 완료가 아니다. 기준 SHA/브랜치/HEAD는 .git이 없어 확인 불가이며 원격 push·release·운영 DB 적용을 수행하지 않는다.

## 사용법·집계 기준

공동선별비 검토 → 비용 대사에서 귀속 시작월·종료월과 시설을 선택한다. 비용의 귀속월은 양 끝을 포함한다. 시설을 생략하면 현재 조직 전체이며 조건 변경 시 이전 결과를 지운다. 원본 ID/번호/시설 검색, 후보/제외/보류/보완 필터, 50행 페이지 이동을 제공한다. 상세에서 원본 증빙, 의뢰/정상/실패/취소 이체, 재이체 원거래 ID, 신청별 비용 배부와 해제 이력을 확인한다. 비용 분류와 신청 상태는 한국어로 표시한다.

이체는 비용에 연결된 모든 기록을 날짜에 관계없이 표시한다. 예를 들어 3월 비용의 4월 재이체도 3월 귀속 비용 조회에 포함한다. 이는 이체일 기준 현금흐름 보고서가 아니다. SUCCESS만 정상 기록 합계에 포함하며 FAILED/CANCELLED/REQUESTED는 별도 상태 합계이다. 실패 1,000원과 후속 정상 재이체 1,000원을 합쳐 2,000원으로 인정하지 않는다. 재이체 연결은 기록 ID와 실제 등록 거래번호를 보여주며 같은 금액만으로 추정 연결하지 않는다.

검토 후보액은 기존 분리 검토 후보 분류인 경우 min(발생액, SUCCESS 기록 합계), 그 외 제외/미확정 비용은 0이다. 정상 기록 합계와 후보액을 구분하므로 포장비 등에 정상 이체가 있어도 후보로 인정하지 않는다. 실제 은행 확인액이나 최종 정책 적격액은 아니다.

활성 비용 배부만 차감한다. 기록 잔액=비용별 후보액−활성 배부액이며 음수도 그대로 표시한다. 비용별 양의 잔액 합계와 초과 배부 합계를 각각 표시하고 서로 다른 비용끼리 상계하지 않는다. 해제된 배부는 금액을 차감하지 않고 이력으로 남긴다. 기존 신청 철회 시 배부 해제 동작을 사용하며 조회가 원장을 변경하거나 자동 해제하지 않는다.

## 무결성·한계

비용 등록 당시 input_hash와 현재 원본 필드를 비교한다. 비용/분리/이체 증빙의 현재 내용 SHA256과 저장된 해시도 비교하며 같은 파일은 조회 내 한 번만 읽고 검증한다. 관련 없는 모든 PDF 바이트를 일괄 로딩하지 않는다. 누락/변경, 재이체 원거래 연결, 정상 합계의 발생액 초과, 초과 배부와 신청 상태 불일치를 보완 항목으로 표시한다. 수치는 현재 기록의 참고 계산이며 무결성 경고가 있으면 지급 적격으로 해석할 수 없다. 조회가 증빙이나 과거 기록을 복구/수정하지 않는다.

로컬 DB 관리자에 의한 원본과 해시 동시 변경까지 진본 보증할 수 없다. 현재 조회는 승인 snapshot·전자서명·은행 원장 검증이 아니다. 지급액은 null, operational_approval=false, payment_verified=false를 유지한다. P-01~15와 독립 인증/직무분리 미확보에 따른 승인·지급·공식 출력 차단도 유지한다. 비용 항목별 최종 정책, 예산 그룹 누적·기관 비용 전수 대사 및 현장 인수는 남아 있다.

## 구현·시험

GET /api/org/{org}/sorting/cost-review?start=YYYY-MM&end=YYYY-MM&facility_id=ID(시설 선택). 기존 세션/조직/시설과 기능 OFF를 검사하고 일관된 SQLite 읽기 transaction에서 조회한다. 금액은 Decimal 60자리 문맥의 문자열이며 float를 사용하지 않는다. 신규 테이블/migration/의존성이 없고 기존 비용 등록·이체·배부 API 계약을 변경하지 않는다. 기존 OCR 엔진·실행 정책도 변경하지 않는다.

BR-401/402/403 및 M2-A를 epms/sorting_cost_review.py, sorting_api.py와 web/sorting-cost-review.tsx/sorting.tsx에서 보완했다. tests/test_sorting_cost_review.py는 실패→재이체, 귀속월과 이체일 차이, 소수 원값, 부분 배부·철회 해제, 제외/보류/미이체, 해시 변경·음수 잔액·초과액 비상계, 잘못된 월·조직·시설·토큰 및 조회의 읽기 전용을 시험한다. tests/browser/sorting.spec.ts는 비용 등록과 실패/재이체 이후 실제 화면의 후보액·상태별 합계·상세 연결·원본 다운로드·필터를 검증한다.

신규 Python 8 PASS(3.55초), 전체 Python 198 PASS(78.06초, 기존 경고 3개), 프런트엔드 11 PASS, TypeScript/Vite build PASS이다. `EPMS_TEST_URL=http://127.0.0.1:18767 npm run test:e2e -- tests/browser/sorting.spec.ts`는 6 PASS(13.0초). 금액 분류/신청 상태 한국어 표시를 보완한 최종 화면 빌드도 PASS이다. 전체 Python은 번들 Python에 PYTHONPATH=.deps-local;.deps-desktop 및 PYTHONUTF8=1을 지정한 `-m pytest -q`, 프런트엔드는 `npm test`와 `npm run build`를 사용했다. 로그는 output/sorting-tests/cost-review-*.log이고 모두 별도 합성 DB이다. 실제 급여/은행/기관 PC·네이티브 창의 인수 결과가 아니다.

기능 OFF 기존 업무 Edge 9 PASS(20.3초), 최신 Lite exe 별도 합성 DB의 검토 흐름 Edge 6 PASS(12.4초)이다. cost-review-off-edge.log 및 cost-review-packaged-edge.log를 참조한다. 패키지 기동 점검 도구에도 새 cost-review API의 통화 단위·운영 차단·지급액 null 검사를 추가했다. 공개 release 또는 운영 전환 승인으로 해석하지 않는다.
