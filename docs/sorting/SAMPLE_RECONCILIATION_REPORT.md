# 제공 자료 대사 결과와 검증 범위

2026-11-23 [실제 스캔 OCR 실행 확인](PDF_PAGE_REVIEW.md): 4쪽 모두 환경 경고·후보 0행이며 전수 대사는 미완료이다. Windows PowerShell 실행 제한을 변경하지 않았다.

2026-11-22 로컬 읽기 전용 분석 결과이다. 원본을 변경하거나 외부로 업로드하지 않았다. 실제 업체명·신고 원번호·주소·지급 개인정보가 있는 행별 결과는 ignore 대상 output/sorting-private에만 보관한다.

## 두 Excel의 전체 행 비교

두 파일 모두 합계·보조 머리글을 제외한 112행·126,524kg이다. 신규 sorting_reconciliation 엔진으로 정규화 신고번호 후보를 대응하면 112건 모두 중량이 일치하고 수량 미확인 행은 0건이다. 서로의 행 순서에 의존하지 않고 원본 시트·행·셀·원문을 보존했다. 수식은 실행하지 않았다.

그러나 112건 모두 실제 품목란 번호가 없어 ITEM_LINE_UNVERIFIED이다. 원문 품명 표기 차이도 자동 동등성으로 처리하지 않았다. 따라서 표 간 수치 대응은 확인했지만 신고필증 품목란·실제 선별·실수출 연결이나 지원 적격을 확정한 결과가 아니다. 기존 33건 부분 신청, 0.4kg 원본 차이 및 실제 지급액을 이 결과로 확인했다고 해석하지 않는다.

## PDF 및 HWP 확인 범위

sample2 PDF는 33개 파일·339쪽이며 고유 hash는 32개다. 같은 파일의 중복 사본을 포함한 쪽수이다. 문자층이 확인된 쪽은 4쪽, 문자층이 없는 쪽은 335쪽이다. 원본 인벤토리 hash를 현재 파일과 다시 비교해 일치함을 확인했다. HWP 2개는 본문 미해석 상태이다.

문자층 부재만으로 문서 내용이나 오류를 판정하지 않는다. 이번 단계에서 PDF OCR 전수·신고/급여/이체/비용의 전체 대사와 기관 담당자의 원본 확인을 완료하지 않았다. 실제 자료의 최종 대사 및 현장 인수는 NOT_VERIFIED로 남긴다.

## 재현 및 산출물

도구는 tools/sorting_sample_check.py이다. 앱 실행과 동일한 PYTHONPATH 및 Python 환경에서 실행한다. paired-table-reconciliation.json은 원본별 hash와 행별 결과, coverage.json은 실제 확인 범위, sample-check.json은 기존 독립 집계 결과를 output/sorting-private에 기록한다. 공개 repo·패키지에는 복사하지 않는다.

앱의 자료 대사 화면은 두 원본 업로드→공식 시트 선택→행 대응·중량 비교→CSV 저장을 지원한다. 미리보기와 내보내기는 신청·예약·승인 DB를 변경하지 않는다. CSV의 식별자·수량은 작은따옴표 접두로 텍스트 원값을 보존하고 수식 실행을 방지한다. 대사 hash는 결과 재현 참조이지 전자서명이나 법적 원본 인증이 아니다.
