# 단일 PC 서면 결재·외부 지급 결과 원장

2026-11-23. 시스템 안의 전자승인·자동 집행 대신 기관의 실제 서면 결재와 은행 처리 결과를 기록하는 기능이다. 별도 사용자 DB나 공용 서버를 요구하지 않는다. 기존 단일 PC·SQLite·증빙 저장·직접/간접실적 계산을 유지한다. 개인 신원이나 서명·은행 결과를 프로그램이 인증한다는 뜻은 아니다.

## 1. 업무 순서

1. **계산·귀속 검토**: 신고 품목란과 선별장 작업/출고를 예약하고, 회원별 귀속·비용·근거를 기록한다. 기존 모의계산을 참고하되 명세의 참고 입력액은 자동 검증 산정액이 아니다. 실제 적용 기준·단가·산식·한도·절사·공제/환류 및 근거 문서번호를 별도로 남긴다. 미확정 값을 임의로 확정하지 않는다.
2. **준비 대장**: 회원별 명세 검토본을 보존하고 지급 준비 대장에 상신 제안액을 기록한다.
3. **상신 고정·출력**: 같은 신청에서 ‘검토자료 보관 → 서면 결재·지급 → 새 상신본 고정’을 연다. 준비 대장·문서번호·실제 상신일·적용 기준/쟁점·사유를 입력한다. 귀속과 비용 배부가 빠진 상태는 먼저 정리한다. 제안 금액의 미확인은 문서에 미확인으로 표시한다.
4. **외부 서면 결재**: ‘고정 상신자료’를 Excel 또는 인쇄/PDF 저장으로 출력한다. 담당·검토·결재란, 신고·선별장·회원 물량, 참고액/제안액과 보완 사항을 기관 절차로 검토·결재받는다. 문서 재출력은 새 상신/승인이 아니다.
5. **결재 결과 입력**: 문서번호·결재일·실제 결재 스캔본/증빙·결재 근거와 회원별 가결/보류/부결·금액을 기록한다. 제안액과 다르거나 제안액이 미확인이면 사유가 필요하다. 가결 기록은 ‘외부 서면 가결’이며 시스템 승인 상태가 아니다. 같은 서면의 오기는 ‘입력 오기 정정’, 실제 재결재는 새 문서·증빙·근거로 이전 기록에 연결한다.
6. **지급자료 출력·외부 송금**: ‘서면 결재 기준 지급자료’를 출력하고 실제 은행/회계 절차에서 송금한다. 수혜 계좌의 실제 확인과 이체는 기관/은행에서 수행하며 이 프로그램은 송금하지 않는다. 지급 전 최신 원장·기지급·외부 중복 자료를 다시 대사한다.
7. **실제 은행 결과 입력**: 송금계좌 관리참조·은행 거래번호·실제 이체일·거래 총액·상태·이체증빙 및 신청/회원별 배부액을 입력한다. 성공/실패/은행 취소를 구분한다. 실제 이체 금액과 모든 배부액 합계가 같아야 한다. ‘외부 지급 결과 명세’를 출력해 결과를 보관한다.

## 2. 금액을 분리한다

| 항목 | 의미 |
| --- | --- |
| 계산 참고 입력액 | 기존 명세에 기록한 참고값. 정책 산식에 의해 자동 심사/승인된 값 아님 |
| 상신 제안액 | 고정 당시 지급 준비 대장에 입력한 값 |
| 서면 결재액 | 실제 결재 문서에 따른 가결 금액의 입력 기록 |
| 지급 기록액 | 유효한 성공 이체 기록의 해당 회원 배부액 합계 |
| 환수 기록액 | 실제 환수 입금으로 기록한 금액. 무효 처리한 입력은 제외 |
| 순지급 기록액 | 지급 기록액−환수 기록액 |
| 미지급 잔액 | 서면 결재액−순지급 기록액. 환수 뒤 잔액이 생겨도 기존 결재로 자동 재지급하지 않음 |

예: 참고/제안 1,000,000원 → 서면 결재 900,000원 → 실제 지급 기록 600,000원이면 미지급 잔액 300,000원이다. 이후 환수 100,000원을 등록하면 순지급 기록 500,000원, 결재액 대비 잔액 400,000원이지만 추가 지급을 기록하려면 새 외부 결재 결과가 필요하다.

외부 결재·실제 은행 금액은 원 단위 정수로 기록하며 소수 참고 계산을 임의로 반올림하지 않는다. 금액 공란과 입력한 0을 구분한다. 수령 주체·적격성·정책·세액/환류/공제의 실제 결정은 외부 결재 근거에 따른다. 프로그램이 미확정 정책을 승인 프로파일로 전환하지 않는다.

## 3. 중복·초과·변경 통제

- 상신본을 고정하면 원 신청의 일반 철회/반려, 행 반려에 의한 물량 해제, 귀속 전체 변경 및 새 비용 배부를 막는다. 기존 예약량은 그대로 사용하며 별도 물량을 새로 만들어 중복 집계하지 않는다.
- 현재 서면 결재 기록의 가결 회원·결정액·최신 결재 ID를 검사한다. 분할 지급 누적 순지급액이 결정액을 넘지 않게 한다. 정상 이체가 아닌 실패/취소는 지급액에 합산하지 않는다.
- 동일 PC/DB에서 송금계좌 관리참조·거래일·거래번호를 정규화해 중복을 검사한다. 같은 실제 계좌에는 항상 같은 관리참조를 사용한다. 잘못된 참조/거래번호 입력, 별도 DB/다른 사업의 지급까지 은행과 독립 검증하는 기능은 아니다.
- 금액·증빙·문서·일자·회원/신청 범위를 검사하고 모든 저장은 BEGIN IMMEDIATE transaction으로 처리한다. 동일 요청키/본문 재시도는 같은 결과를 반환한다. 동시 결재 등록은 이전 결재 ID로, 동시 지급은 현재 누적액으로 통제한다.
- 상신 후 원본·회원·계약·신고·비용·준비 대장이 바뀌어도 상신본은 덮어쓰지 않는다. 변경을 표시하고 외부 재검토/재결재 근거를 요구한다. 결재 후 원본 변경이 있는 상태에서 이미 수행된 송금을 기록할 때도 실제 사실과 변경 대사 사유를 남긴다. 상신일 전 결재·결재일 전 이체도 별도 근거 없이는 기록하지 않는다.
- 미지급 상신 취하는 실제 취하/취소 증빙과 사유를 기록한다. 이 단계 자체는 원 신청 예약을 해제하지 않는다. 취하 이후 원 신청에서 사유를 남기고 명시적으로 철회해야 해제된다.
- 성공 지급이 한 번이라도 기록된 건은 입력 정정·전액 환수 뒤에도 일반 취하로 자원을 다시 가용량으로 바꾸지 않는다. 환수 완료를 물량 재지원 허가로 간주하지 않는다. 별도 정책상 재사용/조정 승인은 이 기능에서 자동 구현하지 않았다.

## 4. 실패·재이체·정정·환수

- **실패/은행 취소**: 실제 결과 증빙과 함께 기록한다. 재이체는 실패/취소 원거래 ID와 새 실제 은행 거래번호를 연결한다. 원거래의 회원별 재이체 가능액을 넘지 못한다.
- **지급 입력 무효**: 잘못 등록한 성공 이체 입력 전체를 정정하는 보상 기록이다. 은행 송금 취소가 아니다. 원 기록을 삭제하지 않는다. 같은 실제 거래를 바르게 다시 기록하려면 ‘대체할 지급 기록 ID’를 명시한다. 이미 환수 이력이 연결된 지급 전체 무효는 제한된다.
- **실제 환수**: 원 지급·회원별 가능액 이내에서 실제 입금 거래번호·일자·증빙을 기록한다. 원 지급보다 빠른 환수일은 허용하지 않는다. 환수 거래도 중복 검사한다.
- **환수 입력 무효·대체**: 환수 입력 오기는 원 환수를 명시해 전체 입력 무효를 남긴다. 이는 실제 입금 취소가 아니다. 무효 뒤 순지급액이 현재 결재액을 초과하게 되면 그 금액을 포괄하는 외부 결재 근거가 먼저 필요하다. 같은 실제 환수 거래를 재입력할 때는 ‘대체할 환수 기록 ID’를 명시한다. 원 환수·입력 무효·새 기록 모두 보존한다.
- **결재 입력 정정**: 같은 실제 문서를 다시 해석해 오기를 바로잡는 경우 최신 결재 기록에 ‘입력 오기 정정’을 연결한다. 실제 변경 결재와 구분한다. 어느 경우든 현재 기록된 순지급액보다 결정액을 줄일 수 없다. 실제 환수 등 선행 근거를 먼저 기록한다.

## 5. 합산·명세·증빙

동일 품목(org) 안에서 여러 신청/회원의 한 은행 송금 거래를 합산 배부할 수 있다. 거래 총액과 배부 합계가 일치해야 하며 각 신청의 결재 잔액을 함께 검사한다. 회원 전용 Excel/PDF에는 본인 귀속·금액과 해당 배부만 표시하고 다른 회원/다른 신청의 거래 전체 금액을 노출하지 않는다.

현재는 **서로 다른 품목에 걸친 하나의 합산 송금**, **여러 원 지급 거래를 하나의 환수 입금으로 묶는 일괄 배부**는 지원하지 않는다. 같은 거래를 품목/원 지급별로 임의 중복 등록하면 안 된다. 해당 거래는 원본 전체를 대사한 뒤 향후 공통 은행 원장 확장이나 기관의 실제 거래 분리 절차가 필요하다.

결재·이체·정정·환수·취하 증빙은 파일 등록 또는 기존 증빙 ID로 연결하고 원본 다운로드 버튼에서 확인한다. 원본 바이트와 당시 해시가 달라지면 경고하고 새 지급 기록에서 결재 증빙 무결성을 검사한다. 원본 전체에는 다른 회원의 계좌/금액이 있을 수 있으므로 회원 교부에는 전용 명세를 사용한다. 원본 PDF를 자동으로 개인정보 가림 처리하는 기능은 아니다.

고정 상신자료는 당시 제안·근거로 재출력하고 이후 결재/지급 금액으로 덮어쓰지 않는다. 지급자료/결과 명세는 문서·결재 기록 ID와 현재 기록 기준 금액을 표시하므로 지급 전에 실제 기지급과 다시 대조한다. 재출력만으로 새로운 결재/송금/이체 기록이 생성되지 않는다. 기관 내부 결재용 자료이며 제공되지 않은 2027 공식 신청서·발급 확인서를 임의로 대신하지 않는다.

## 6. 저장·백업·운영 범위

PAPER_SUBMISSION/PAPER_DECISION/PAPER_BANK_RESULT/PAPER_BANK_ADJUSTMENT/PAPER_SUBMISSION_CLOSE 종류의 append-only sorting_records를 사용한다. 기존 SQLite schema와 증빙 blob 저장을 사용하며 새 테이블/migration/외부 의존성은 없다. 원문 해시·작성 표기·시각·사유·이전 결정/거래 참조를 보존한다. 로컬 관리자가 원문과 해시를 함께 바꾸는 행위까지 방지하는 전자서명/독립 인증은 아니다.

원장 DB와 등록된 증빙은 함께 백업/복원한다. 여러 검증 ZIP을 서로 다른 업무 DB로 병행 운영하지 말고 **권위 있는 업무 DB 하나**를 정한다. 새 빌드의 검토 실행 스크립트는 별도 data/sorting-review.db를 사용하므로 기존 실제 원장은 프로그램 종료·백업 후 기관의 정상 복원 절차로 이관해야 한다. 실제 자료를 자동 덮어쓰지 않는다.

기존 계산/신고/제출/직접·간접실적과 정책 참조 프로파일은 그대로 유지한다. 기존 전자 승인/지급/official endpoint는 여전히 차단한다. 새 화면은 기관이 이미 수행한 외부 결재·이체 결과의 근거 원장이다. 독립 로그인/전자결재/자동송금/실시간 은행·타 기관 원장 검증은 구축하지 않는다.
