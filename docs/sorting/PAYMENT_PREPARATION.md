# 지급 준비 검토 대장 사용법

2026-11-23 최신 보완: 이 준비 대장 다음의 서면 상신/외부 결재/외부 지급 결과 기록을 추가했다. 아래 실제 지급 아님은 준비 대장 자체의 역할이다. 상세는 [PAPER_WORKFLOW.md](PAPER_WORKFLOW.md), 최신 검증은 IMPLEMENTATION_STATUS.md를 따른다.

신청·명세·준비의 미확인/변경 사항을 함께 확인하려면 [지급 준비 종합 점검](READINESS_REVIEW.md)을 사용한다. 해당 점검 역시 운영 승인이나 지급 가능 판정은 아니다.

2026-11-23. 현재 구현 가능한 승인 전 검토본 고정·지급 준비 기록 기능이다. **송금·운영 승인·지급 확정·예산 예약 기능이 아니다.** ‘입력 검토 완료’도 정책·자격·은행·중복지원 심사 완료를 의미하지 않는다.

## 사용 순서

1. 회원별 지급명세에서 귀속량·비용·근거를 검토하고 명세 검토본을 보존한다.
2. 같은 신청을 선택한 상태에서 ‘검토자료 보관 → 지급 준비 대장’을 연다.
3. ‘명세로 새 준비 대장 만들기’를 펼쳐 기준 명세와 작성 사유를 입력한다. 현재 신청/귀속 버전에 대응하는 명세만 사용할 수 있다. 이미 활성 준비 대장이 있으면 기존 대장을 선택한다.
4. ‘현재 준비정보 불러와 편집’을 누른다. 저장 당시 회원명·사업자번호·귀속량은 고정되며 회원을 임의 추가·삭제할 수 없다. 수령 주체/적격성은 기관 정책과 증빙으로 별도 판단해야 한다.
5. 회원별 **수동 준비액**, **준비 예정일**, **금액·서류 검토 근거**, **서류목록 로컬 검토 기록**을 입력한다. 준비액은 승인액/산정된 지원 한도가 아니며 참고액에서 자동 복사하지 않는다. 예정일은 실제 지급일이 아니다. 계좌·은행 거래·실제 지급 결과를 이 화면에 입력하지 않는다.
6. 사유와 준비 상태를 저장한다. 탭 이동 중 편집 내용을 유지하고, 편집을 불러온 개정 번호로 동시 수정을 검사한다. 다른 창에서 먼저 수정했다면 새 내용을 다시 확인한다. 새로고침·신청 변경 시 미저장 편집은 보존하지 않는다.
7. 사무국 전체 또는 회원 전용 검토본을 선택해 Excel·인쇄/PDF 저장으로 출력한다. Excel에는 기준 명세의 신고·시설·물량·비용 근거도 포함한다. 인쇄 대장에는 기준 명세 번호와 당시 보완·보류 내용을 표시한다. 회원 전용 출력에는 다른 회원의 준비액·근거·내역을 제외한다.

## 상태와 미확인 처리

| 상태 | 의미 |
| --- | --- |
| 준비 작성 중 | 미확인 금액·예정일 등을 수집하는 중 |
| 준비 보완 | 원본 변경이나 누락 사항을 추가 검토하는 중 |
| 준비 입력 검토 완료 (미승인) | 필수 준비 입력을 로컬에서 검토했다는 기록. 운영 승인이나 실제 지급 완료 아님 |
| 준비 취소 | 이 준비 대장을 종료. 다시 열지 않고 필요하면 새 대장을 생성 |

입력 검토 완료에는 모든 회원의 양수 준비액·예정일·검토 근거·로컬 검토 기록과 기준 명세의 미귀속 물량/비용 해소가 필요하다. 기준 명세에 실제 수출이행·확인서·외부원장·정책 보류가 남아 있으면 화면과 출력에서 계속 확인할 수 있다. 이 상태 저장이 해당 보류를 해결하지 않는다. 비용 미등록 또는 정책 미확정을 금액 0으로 바꾸지 않는다.

준비액 공란은 미확인(null), 명시한 0은 수동 입력 0이다. 금액이 미확인인 회원이 포함되면 합계를 미확인으로 표시한다. 알려진 일부 금액만 더해 전체 지급 준비액인 것처럼 표시하지 않는다. 준비액을 입력할 때는 근거를 적는다.

## 고정·변경·취소 통제

- 기준 명세의 당시 원문을 준비 대장에 고정한다. 이후 회원명·신고·시설·증빙·비용·정책·예약 pool·신청/귀속 버전 변경을 감지하면 보완/취소만 기록할 수 있다. 새 원본으로 진행하려면 귀속·명세를 재검토하고 새 대장을 만든다.
- 한 신청에는 활성 준비 대장을 하나만 둔다. BEGIN IMMEDIATE, 대장 revision 및 요청키로 동시 생성·개정·재전송을 통제한다. 같은 키/본문의 재시도는 같은 결과를 반환하고, 키가 같고 내용이 다르면 거절한다.
- 변경은 PAYMENT_PREPARATION_REVIEW 종류의 append-only sorting_records로 보존한다. 기존 대장을 덮어쓰지 않고 원문 해시·작성 표기자·시각·사유·이전 개정 참조를 남긴다. 이는 독립된 사용자 인증이나 전자서명은 아니다. 기관 로컬 관리자에 의한 원문과 해시 동시 변경까지 진본 보증하지 않는다.
- 준비 생성·개정·취소는 원 신청의 revision·물량 예약·비용 배부를 변경하지 않는다. 취소 후 새 준비 대장은 만들 수 있지만 같은 원 신청의 물량 예약은 그대로 유지된다.
- 일반 검토본 보존에도 준비 대장의 기록을 포함한다. 준비 자체의 기준 검증에서는 준비 기록을 제외해 자신의 상태 저장만으로 기준이 변경된 것으로 오인하지 않는다.

이 통제는 **검토 대장 중복 작성 방지**이다. 실제 지급완료 물량 소비, 중복 송금 확정 방지, 다른 PC/DB/타 사업의 공통 지급 원장을 구현한 것은 아니다. 승인액/실제 지급액은 null이고 실제 지급결과 확정·official 출력은 403으로 차단한다.

## 남은 운영 연결

확정 정책과 수령 주체/단가/산식/한도/절사/환류/중복 범위, 독립 사용자·직무분리가 갖춰지면 승인 불변본 → 지급 전 물량·비용 점유 → 보조금 전용 회차·거래 배부 → 실제 지급결과 확정 → 부분 지급/실패·재이체/정정·환수 순으로 연결한다. 현재 검토 입력 상태를 운영 승인으로 재해석하지 않는다. 실제 은행·기관 사본·프린터/네이티브 창 인수는 별도이다.
