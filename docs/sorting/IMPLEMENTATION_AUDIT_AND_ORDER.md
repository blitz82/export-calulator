## 변경 경계와 검증 기록

새 Python 모듈: sorting_policy_review, sorting_snapshots, sorting_group_review, sorting_facility_review, sorting_contract_review. 신규 테이블/migration/의존성 없이 기존 sorting_records를 종류별 append-only 이력으로 사용한다. 기존 시설/계약/예약 API는 유지하고 개정/출고 조회/비교 API를 추가했다. 새 시설 CAS는 기존 행 ID와 FK를 유지하며 이전 원문은 이력에 보존한다. 기존 수출 계산/저장/제출/OCR 계약은 변경하지 않는다.

검토 보존본은 로컬 기준선이며 승인 확정본이 아니다. JSON은 관련 업무 원문을 포함해 기관 내 보관 대상이다. 회원 연락처처럼 판정에 불필요한 필드는 보존본에서 제외한다. 파일 원문을 보존본에 복제하지 않고 해시와 DB 증빙 ID로 연결한다. 로컬 관리자가 원본과 해시를 함께 바꾸는 공격까지 진본 보증할 수 없다.

시험은 tests/test_sorting_governance.py와 기존 전체 회귀, tests/browser/sorting.spec.ts의 연결 흐름으로 확인한다. 최초 전체 회귀에서 확인서 품목 불일치 원본 보존을 막는 회귀 1건과 JSON 파일명 규약 불일치를 발견해 수정했다. 이후 전체 210, 추가 전략 포함 211 Python과 Edge 7 PASS를 확인했고, 마지막 전역 신고 중복 원본 처리 보완을 포함한 최종 결과는 IMPLEMENTATION_STATUS.md/TEST_REPORT.md 및 output/sorting-tests/governance-*.log를 따른다.

최종 소스에서 `python -m pytest -q`: **212 PASS**(기존 198 + 새 14, 82.36초, 기존 경고 3개). `npm test`: **11 PASS**, `npm run build`: **PASS**(기존 큰 청크/use client 경고 유지). `EPMS_TEST_URL=http://127.0.0.1:18767 npm run test:e2e -- tests/browser/sorting.spec.ts`: **7 PASS**(15.3초). Python은 기존 번들 런타임과 PYTHONPATH=.deps-local;.deps-desktop, PYTHONUTF8=1로 실행했다. 새 연결 흐름은 정책 초안→개정 계약→출고분 예약→계약 연결→검토본→시설 개정 비교/후보→그룹 계산까지 검증한다. 전체 Python에는 기존 신규/0003 사본 이관/백업복원 시험도 포함되어 있으며 실제 운영 DB를 연 결과가 아니다.

전역 유효 신고가 복수이거나 신고 논리키가 바뀌면 검토본 비교는 상한을 미확인으로 남긴다. 그룹 계산은 모호한 유효 원본을 임의 선택하지 않고 거절한다. 이전 1,000→900kg 정정의 초과 100kg은 검토 후보로 남기되 물량 해제·금전 환수는 실행하지 않는다. 정책·원장 해시는 기록 비교용이며 실제 승인 증거를 대신하지 않는다.
