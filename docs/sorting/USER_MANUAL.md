# 공동선별비 검토 사용법

현재 권장하는 단일 PC 업무는 [서면 결재·외부 지급 결과 원장](PAPER_WORKFLOW.md)이다. 검토자료 보관 → 서면 결재·지급에서 상신본 출력, 실제 서면 결재 결과/증빙 입력, 지급자료 출력, 외부 이체 결과/잔액/정정·환수를 기록한다. 전자승인·자동송금 기능이 아니다.

선택 신청·명세·준비의 미확인 사항을 함께 대조하려면 [지급 준비 종합 점검](READINESS_REVIEW.md)을 참조한다. 현재 원장의 읽기 전용 점검이며 지급 가능 판정은 아니다.

명세 검토본을 기준으로 회원별 준비액·예정일·준비 상태를 기록하려면 [지급 준비 검토 대장](PAYMENT_PREPARATION.md)을 참조한다. 검토자료 보관 → 지급 준비 대장에서 사용하며 실제 송금·지급 확정은 아니다.

회원별 물량·비용 귀속과 검토 지급명세 출력은 [회원별 귀속·지급명세 사용법](BENEFICIARY_STATEMENTS.md)을 참조한다. 검토자료 보관 → 회원별 지급명세에서 사용하며 실제 보조금 지급 확정은 아니다.

## 초보 담당자 화면

첫 화면은 담당자 업무흐름이다. ‘접수·기초정보 / 서류·물량 확인 / 신청 연결 / 비용·보완 검토 / 검토자료 보관’에서 업무를 선택하면 해당 도구를 표시한다. 나머지 기존 도구는 ‘전체 도구’를 펼쳐 연다. 기존 회원사 직접·간접실적 메뉴와 계산 규칙은 변경하지 않는다.

상단 ‘검토할 신청’에서 연도·품목·상태를 확인하여 선택한다. 선택은 공동선별비 탭 이동 중 유지되며 새로고침/다른 루트 메뉴 이동까지 영구 저장하는 기능은 아니다. 연결 시설·품목·작업일은 상세에서 확인한다. ‘지금 할 일’은 선택 신청 검토 API의 활성 행에 표시된 확인 사항 중 원본·증빙 변경을 우선 제시하고, 그 외는 서버 순서를 따른다. 이는 전체 심사 순서를 판정하는 엔진이 아니다. 정책·운영 판단 보류와 외부 확인 필요 항목은 구분해 표시한다. 조회 오류·로딩을 검토 완료로 표시하지 않는다.

‘해당 행 확인하기’는 같은 신청의 필터·페이지를 해당 행으로 이동하고, 이행·확인서 문제는 해당 입력 상세를 펼친다. 원본 문제는 원본 비교 상세를 연다. 행별 확인 항목이 없어도 계약·비용·중복·정책 등 전체 심사가 끝났다는 뜻은 아니다. 철회/반려된 신청에는 계속 처리하도록 권하지 않는다. 미확인 비용은 0으로 채우지 않는다.

업무 안내는 ‘준비할 서류 / 꼭 확인할 것 / 진행 기준’을 먼저 표시하고 보완·정책 설명은 펼쳐 본다. ‘다음 안내 보기’는 설명만 이동하며 실제 업무 완료 기록을 만들지 않는다. ‘지금 할 일’·숫자 요약 역시 신규 승인·지급·은행 대사를 수행하지 않는다. 서류 안내는 확정된 2027 필수 첨부 목록이 아니다.

현재 구현 수준, 이번 순차 보완 기능과 남은 작업은 [구현 분석·진행 순서](IMPLEMENTATION_AUDIT_AND_ORDER.md)를 참조한다. 정책 검토에서 초안을 기록하고, 비용·거래·생산에서 기존 기록을 선택해 개정한다. 시설·작업에서 시설 변경 이력을 남기고, 신청 검토에서 행별 계약 연결과 검토본 보존/변경 비교를 사용한다. 그룹 모의계산은 실제 예산 집행이 아닌 가상 검토이다.

비용 원본과 이체/배부 내역 확인은 [비용 대사 사용법](COST_RECONCILIATION.md)을 참조한다.

생산자 입고 파일 등록은 [CSV 열 매핑과 재전송 사용법](INTAKE_CSV_IMPORT.md)을 참조한다.

기간·시설별 생산/정산 검토 수치는 [검토 통계 사용법과 집계 기준](REVIEW_DASHBOARD.md)을 참조한다.

여러 입고·작업을 연결하는 화면은 [복수 원물 선별 사용법](PRODUCTION_REVIEW.md)을 참조한다.

페이지별 PDF 원본 대조와 Excel 후보 비교는 [PDF 페이지 검토 사용법](PDF_PAGE_REVIEW.md)을 참조한다.

기능은 기본 OFF이다. 별도 시험 DB에서 EPMS_SORTING_ENABLED=1로 실행하면 공동선별비 검토 메뉴가 나타난다. ON이어도 승인·지급·공식 출력은 불가능하다. 기존 수출실적 메뉴는 그대로 사용한다.

검증 ZIP을 풀고 Start-EPMS-Sorting-Review.cmd를 실행하면 data/sorting-review.db라는 별도 DB로 검토 기능을 연다. 기존 운영 DB를 자동으로 열지 않는다. 기존 회원·신고의 사본을 사용하려면 프로그램 종료 후 기관의 정상 백업·복원 절차로 별도 검토 DB를 준비한다.

1. 기존 회원사 명부에 회원을 등록한다.
2. Excel·증빙에서 지정증빙과 작업증빙을 올리고 표시된 증빙 ID를 확인한다. 원본은 로컬 DB에 보존된다.
3. 시설·작업에서 회원 사업자번호·품목·지정번호·유효기간·증빙 ID로 시설을 등록한다. 계약 기준일과 적격성은 미확정이다.
4. 작업·ERP 번호, 선별일, 확인물량 kg, 품목과 작업증빙을 등록하거나 Excel 시트·행을 선택해 작업으로 가져온다. 자료를 가져왔다고 실물 연결이 확인된 것은 아니다.
5. 수출 매칭·예약에서 신고번호를 검색하고 원본 검증문자·품목란·중량·버전을 대조하여 후보를 선택한다. 작업과 이번 신청량을 지정한다. 2026 프로파일은 2026년, 2027 초안은 2027년으로 선택한다.
6. 신청 검토에서 정책·확인서·수출이행·외부 중복원장 보완 항목을 확인한다. 예약→검토→보완/검토자료 제출로 처리하며 철회·반려는 예약을 해제한다. 검토자료 제출은 공식 신청·승인이 아니다.
7. 비용·거래·생산에서 비용 원본, 과거 비용 이체증빙, 비용 배부, 계약·계획·농가 정산·사무국 발급 확인서·제재 사건을 기록한다. 숫자 0과 공란을 구분하며 불명확한 비용을 임의 인정하지 않는다. API는 신규 버전 이력을 지원한다.
8. 검토 Excel에는 검토용 / 지급 미확정을 표시한다. 프로그램 출력은 사무국 발급 확인서가 아니다. 원본 증빙에는 개인정보가 있을 수 있으므로 내려받은 파일의 보관 범위를 확인한다.

모의계산은 Q×U와 min(C,Q×U)를 분리 표시한다. C 공란은 미확인이고 C=0은 확인한 비용 0이다. 모의 입력은 증빙심사 결과가 아니며 실제 지급액으로 사용할 수 없다. 2026 단가를 2027 확정 단가로 적용하지 않는다.

생산 확장 입력은 kg 입고→선별·재선별→출고를 기록한다. 적합·내수·비상품·감모·보류 재고의 합계는 원물과 같아야 한다. API는 복수 원물을 지원한다. 기본형과 동일한 작업·수출 예약 원장을 사용한다. 이월 재고 재사용·복잡한 분할 편집과 원본 옆 다대다 편집 화면은 추가 구현 대상이다.

## 다대다 배분과 행별 보완

신고 후보와 연결 작업을 선택하면 서버가 현재 신고 잔량·작업 잔량·배분 가능량을 보여 준다. 이 잔량은 아직 저장하지 않은 화면 목록을 제외한 조회값이다. 수량을 입력하고 배분 목록에 추가한다. 다른 신고란·작업을 이어서 선택하여 같은 신청에 여러 행을 담는다. 목록 검색·50행 페이지·수량 수정·삭제를 지원하고 다른 검토 탭을 열었다 돌아와도 목록은 유지된다. 품목과 연도·프로파일을 확인한 후 검토 물량 예약을 누르면 전체 행을 한 transaction으로 검증한다. 오류가 있으면 어느 행도 저장하지 않는다.

응답을 받지 못했다면 목록을 수정하지 않고 다시 요청한다. 동일 요청키와 본문으로 이미 저장된 결과를 재사용한다. 화면 목록은 브라우저 메모리에 있어 프로그램 종료·페이지 새로고침 후에는 유지되지 않는다.

신청 검토의 행별 보완·반려에서 각 행을 처리하고 사유를 입력한다. 보완은 물량 예약을 유지하고 반려는 선택 행만 해제한다. 원래 신청량과 현재 예약량을 따로 표시한다. 다른 창에서 먼저 수정한 경우 stale revision을 거절하므로 다시 조회한다. 보완 오류의 행 보기 버튼은 필터·페이지를 해당 행으로 이동한다.

원본·변경 차이에서 신청 당시와 현재 신고 중량, 차이, 선별일·출고일·신고일·원장 기재 선적일·미확인 실제 수출이행일을 대조한다. 기간 밖 작업·출고 역전·교차월은 원본을 바꾸지 않고 검토 사유로 표시한다. 지정 시작일·종료일은 포함 경계로 표시하지만 정책적 자격 기준일 승인과는 별개다. 검토 Excel에도 행 상태·예약 유지/해제·중량 차이와 날짜 대조 시트가 포함된다.

## 실제 수출이행과 사무국 확인서 연결

Excel·증빙에서 이행 증빙 파일을 먼저 등록한다. 비용·거래·생산에서 사무국 확인서의 실제 발급주체·시설·품목·회원·확인기간·물량·중복 기재내용과 원본 증빙 ID를 등록한다. 신청 검토의 각 행에서 이행·확인서 증빙 연결을 연다.

이행증빙 ID, 종류, 실제 수출일 검토값, 사무국 확인서를 선택하고 대조 근거·사유를 적어 저장한다. 한 쪽 자료만 연결한 부분 기록도 가능하며 나머지는 보완 상태로 남는다. 저장은 현재 입력한 연결값 전체의 새 버전이므로 기존 연결을 갱신할 때도 필요한 값 전체를 입력한다. AWB/B/L 운송 보조자료만으로 실제 수출일을 기록할 수 없다. 원장 기재 선적일을 자동 복사하지 않는다.

시설·품목·회원·작업기간이 확인서와 맞지 않으면 원값을 보존하고 보완으로 표시한다. 동일 원본 확인서의 활성 연결량 합계가 확인물량을 넘으면 저장 전체를 거절한다. 같은 파일을 다른 확인서 ID와 더 큰 물량으로 등록해도 한도가 늘어나지 않는다. 동일 파일에 여러 독립 확인서가 포함된 경우 이 버전은 원본 파일별로 보수적으로 묶으므로 개별 확인서 원본을 분리해 등록하고 기관 검토를 거친다. 시스템이 서로 다른 확인서의 물량을 임의 합산하지 않는다.

연결 완료는 로컬 검토기록이다. 실제 발급·검토자 인증이나 공식 수출이행 확인, 운영 승인과 동일하지 않다. 화면의 검토 표기자도 독립 인증된 사용자라는 뜻이 아니다. 정책·외부 중복원장 심사는 별도로 남는다. 승인·지급은 계속 차단되고 미확정 금액은 null이다.

증빙 이력 조회에서 과거 검토값·사유·시각을 확인한다. 연결 철회를 저장하면 현재 연결을 해제하고 과거 기록은 삭제하지 않는다. 증빙 바이트·확인서 기록·원장/시설/작업 변경이나 확인서 새 버전이 감지되면 다시 보완 상태가 된다. 검토 Excel의 행별 증빙 검토기록 시트에도 검토 상태·근거 ID·표기자·시각·사유를 표시한다.

## 두 자료 대사와 인쇄 서식

자료 대사에서 왼쪽·오른쪽 Excel을 올리고 각각 공식 세부 시트를 선택한 후 표 간 대사 실행을 누른다. 원본 행·원문량·정확한 차이와 번호/품목란 미확인·복수 후보·누락을 대조한다. 검색·필터·50행 페이지와 CSV 내보내기를 지원한다. 같은 원본 비교에는 독립 자료 검증이 아니라는 경고를 표시한다. 수식·공란을 0으로 바꾸지 않으며 새 파일 선택 시 이전 결과를 지운다.

이 결과는 표의 대응이며 신고 원본·실물·비용 적격·타 사업 중복 확인이 아니다. 예약·신청을 만들거나 기존 자료를 수정하지 않는다. CSV 식별자·수량은 정밀도 및 수식 주입 방지를 위해 작은따옴표 접두의 텍스트 원값으로 내보낸다.

신청 검토에서 인쇄용 검토 서식 미리보기를 열면 검토 신청서·사무국 확인서 작성 참고 초안·신고별 세부내역이 나타난다. 프레임 안의 검토 서식 인쇄에서 브라우저 인쇄/PDF 저장을 선택한다. A~F와 단가가 미확인일 때 0이나 현재 예약량을 확정값으로 채우지 않는다. 공식 신청서/발급 확인서가 아니며 운영 승인·공식 출력은 계속 차단된다. 기존 검토 Excel은 상세 감사 자료로 함께 사용한다.
