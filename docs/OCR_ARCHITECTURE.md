# 수출신고필증 추출과 검토

## 템플릿과 값의 출처

`epms/ocr_unipass.json`에는 서식 ID, 버전, 제목, 품목 경계, 총계 경계 및 상단 앵커를 둔다. 공식 양식 묶음의 제1호 서식은 수출신고서이고, 3~4쪽에는 적재 전 수출신고필증 갑지 및 을지가 있다. 실제 샘플의 표는 라벨 아래에 값이 배치되며 품목 합계와 신고 전체 합계가 각각 표시된다. 이전 링크는 조회하지 못했고 두 자료의 시행일은 확인하지 못했다. [국가법령정보센터 공식 양식 묶음](https://www.law.go.kr/LSW/flDownload.do?bylClsCd=200203&flSeq=159840053)

| 원본 위치 | 매핑 |
| --- | --- |
| 상단 신고번호·신고일자 표 | 라벨 인근의 다음 줄 값. 바로 이어진 형식과 라벨 행 아래 값 행도 지원 |
| 신고수리일자 | 해당 라벨에 연결한 날짜 |
| 수출화주 블록 | 명시된 사업자등록번호 |
| 대행자·화주·제조자 상호 표시 | 같은 줄에 있는 유일한 문자열 후보 |
| 품명·규격 표제 | 왼쪽 란번호를 품목 식별자로 사용. 우측 총란수는 범위 검사에 사용 |
| 개별 품목 블록 | 세번부호, kg 단위 순중량, USD 표시가 있는 FOB |
| 명시된 일련번호 | 근거가 있는 경우 원본 검토에 표시. 원장 저장 항목으로는 사용하지 않음 |

증거 좌표는 좌상단 기준 `[left, top, right, bottom]` 비율이다. PDFium 문자 사각형은 페이지 경계와 회전을 반영해 변환한다. Windows OCR 사각형은 이미지 크기로 나누며 비영 각도를 보고한 OCR 결과는 위치를 표시하지 않는다. 값이 반복되고 해당 위치를 좁힐 수 없으면 위치를 생략한다. 구현과 시험 결과는 [좌표계 검증](OCR_COORDINATE_SYSTEM.md)에 기록했다. [pypdfium2 API 문서](https://pypdfium2-team.github.io/pypdfium2/) [Microsoft OCR 단어 좌표 문서](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr.ocrword.boundingrect?view=winrt-28000)

전자 텍스트와 좌표가 우선이며, 지원 서식의 누락 필드와 큰 래스터 이미지가 있는 페이지는 Windows OCR로 보완할 수 있다. 같은 필드의 값이 다르면 PDF 값과 Windows OCR 후보를 함께 표시한다. 재시도 조건, 비교 기준, 후보 근거와 검증 범위는 [하이브리드 OCR](OCR_HYBRID_EXTRACTION.md)에 기록했다.

## 사용 방법

신고 원장에서 **PDF에서 가져오기**를 열어 파일을 선택한다. 후보 필드를 선택하면 근거가 있는 항목의 원본 쪽과 사각형이 표시된다. 사각형을 선택하면 연결된 입력칸으로 이동한다. **이 영역 재인식**은 저장된 영역을 확대해 읽고 후보 문자를 표시한다. 확인한 값은 입력칸에서 직접 수정한다. 원본에 위치가 확인되지 않은 항목은 PDF를 직접 탐색해 입력한다.

품목란별 USD와 kg를 확인하고 **승인하고 원장에 등록**을 선택한다. USD 또는 kg를 수정하면 해당 확인이 해제된다. 현재 Windows에서 스크립트 실행이 차단되거나 한국어 OCR을 사용할 수 없으면 원본으로 직접 검토한다.

## invoice2data 검토

고정 버전 검토와 EPMS 독립 구현 시험 결과는 [PHASE 3 기술 실증](INVOICE2DATA_INTEGRATION.md)과 [OCR 의존성 선택](OCR_DEPENDENCY_DECISION.md)에 기록했다.

공식 프로젝트의 템플릿 선택, 필드 및 반복행 추출, `required_fields` 설정을 검토했다. 이번 구현은 EPMS 자체 템플릿과 기존 PDFium·Windows OCR을 활용한다. 위치 증거와 누락을 보존하는 응답 구조, 실제 신고번호와 란번호 단위 보완을 기존 프로그램에 직접 연결할 수 있었다. invoice2data 패키지와 외부 템플릿·소스는 추가하지 않았다. 버전을 고정한 라이브러리 실행 실증과 비교 시험은 남아 있다. [공식 템플릿 문서](https://github.com/invoice-x/invoice2data/blob/master/docs/tutorial.md) [프로젝트 라이선스](https://github.com/invoice-x/invoice2data/blob/master/LICENSE.md)

템플릿 관리자, 서식 버전별 독립 템플릿과 활성화 흐름, 근거가 없는 필드에 대한 임의 영역 지정, 일련번호 원장 영속화는 남아 있다. 대행자·제조자 사업자등록번호와 선적일은 명시 라벨을 처리하며, 실제 문서 검증이 필요하다. 정정 차수·모델·규격 매핑은 남아 있다.
