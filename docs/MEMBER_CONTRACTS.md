# 회원사 계약 관리

왼쪽 **회원사 명부 → 계약서 등록 → 공동선별장 명부** 순서로 이동합니다. 공동선별장 메뉴는 기존 공동선별 기능이 켜진 실행 환경에서 표시됩니다. 계약 기능은 공동선별 기능 설정과 독립적으로 사용할 수 있습니다.

## 등록과 원문 대조

1. 회원사 명부에 당사자를 등록한 뒤 **계약서 등록 → 계약 신규 등록**을 누릅니다.
2. 생산자회원사와 수출업체를 이름·사업자번호로 검색해서 직접 선택합니다. 계약의 역할은 명부의 회원사 유형을 변경하지 않습니다.
3. 계약 연도와 기간 구분을 선택합니다. **연간 계약**은 해당 연도 1월 1일~12월 31일을 자동 입력합니다. **연도 중 체결·기간 직접 지정**은 체결일을 시작일의 기본값으로 사용하며 실제 계약에 따라 시작·종료일을 수정할 수 있습니다. 품목은 통합조직에 등록된 단일 품목으로 고정됩니다. 주요 약정을 입력하고 PDF를 업로드합니다. 파일은 20MB, 1~30쪽까지 지원합니다.
4. 오른쪽 PDF와 입력 내용을 대조합니다. 각 약정의 근거 페이지를 입력하거나 **현재 쪽 지정**으로 연결합니다.
5. 추출 후보는 미확정 정보입니다. **입력 후보 확인**으로 옮긴 값도 원문과 대조해야 합니다. 당사자 후보는 자동으로 회원사에 연결하지 않습니다.
6. 검토 상태와 등록 사유를 입력하고 저장합니다. **확인 완료**에는 한 개 이상의 원문 근거 페이지가 필요합니다.

현재 계약 추출은 로컬 PDF 텍스트와 명시된 한국어 라벨에 기반합니다. 수출신고필증 전용 OCR 양식을 계약서에 적용하지 않습니다. 스캔본·텍스트 추출 실패·라벨 없는 자유 형식 계약은 PDF를 보면서 수동 입력할 수 있습니다. 원본의 외부 전송은 없습니다.

## 조회와 연결도

- 기본값은 오늘(한국 시간) 기준 **유효** 계약입니다. 예정·만료·해지·확인 필요 계약은 상태 필터에서 선택합니다.
- 계약 연도로 목록·연결도를 좁힐 수 있습니다. 계약 연도는 시작일의 연도이며, 상태는 별도의 기준일로 판단합니다. 연도 중 계약과 연간 계약을 함께 관리할 수 있습니다.
- 단일 품목에 여러 HS코드를 사용할 수 있습니다. 입력 화면에 계약 연도의 정책에 등록된 HS코드를 모두 표시하며, 계약 등록으로 계산 정책을 바꾸지 않습니다.
- 회원사 선택·연결도에는 이름과 사업자번호만 표시합니다. 회원사 ID는 내부 참조에만 사용합니다.
- 종료일 미정 계약, 종료일이 지난 자동연장 계약은 **확인 필요**로 표시합니다. 자동연장 조항의 실제 적용을 추정하지 않습니다.
- 연결도 왼쪽은 생산자회원사, 오른쪽은 수출업체입니다. 같은 두 회원사 간 복수 계약은 한 선으로 묶습니다. 양쪽 역할을 맡는 회원사는 역할별로 표시됩니다.
- 업체 칸은 연결 강조, 선은 계약 상세 패널을 엽니다. 이름 정렬·확대·축소·화면 맞춤과 연결 관계 표를 제공합니다. 칸과 선은 Tab 및 Enter/Space로도 선택할 수 있습니다.
- 동일 회원 ID 또는 정상적인 동일 사업자번호의 자기 연결은 생략합니다. 누락·비정상 사업자번호와 중복 명부는 확인 안내를 제공합니다.
- 선은 계약 관계를 나타냅니다. 실제 거래 이행·대금 지급·지원금 적격 판정을 뜻하지 않습니다.
- 수출자료 최종 확정에는 제조자(생산자회원사)와 수출화주 또는 수출대행사 중 **한 회원사 이상**의 유효하고 원문 검토가 확인 완료인 등록 계약이 필요합니다. 제조자와 수출업체가 동일 사업자이면 자기 계약은 생략합니다. 역할·사업자번호·회원사명 대조는 기존 검증을 함께 따릅니다.
- 계약 유효기간은 **선적일**, 선적일이 없으면 **신고일**을 기준으로 확인합니다. 현재 만료되었더라도 수출 당시 유효했던 계약은 사용할 수 있습니다. 종료일 미정·기간 종료 후 자동연장 여부 미확인·수출 당시 해지·다른 당사자의 계약은 통과하지 않습니다.
- 제조자 사업자번호·명칭·회원 역할을 아직 대조하지 못한 경우에도 계약 검증을 통과 처리하지 않습니다. 명부·원문을 먼저 대조하도록 확정 차단 안내(D091)를 표시합니다. 개별·Excel 일괄 등록과 이후 재검증에 같은 규칙을 적용합니다.
- 계약이 없거나 미검토여도 신고 원장 입력·초안 저장은 가능합니다. 기간만 유효하고 원문 검토가 미검토·확인 필요인 계약은 최종 확정에 사용할 수 없습니다. 실제 PDF 확인과 근거 지정 후 확인 완료로 저장하세요. 검증 열에 **확정 차단**과 **계약서 등록 확인** 안내를 표시하고, 최종 확정은 서버에서도 차단합니다. 계약 보완 후 현재 자료를 다시 검토하세요. 계약 수정 이후 오래된 계산 결과로 새 확정을 할 수 없습니다. 이미 보관된 확정본은 원본 기록으로 유지합니다.
- 계약 검사는 금액 귀속 산식을 바꾸지 않고 최종 확정 가능 여부를 검증합니다. 통과 근거인 계약과 수정 차수를 계산 이력에 보존합니다.
- 회원사 명부에서 회원사를 열고 **관련 계약·연결 회원사 조회**를 누르면 양쪽 역할의 관련 계약을 조회합니다.

## 변경과 기록 보존

내용 수정에는 변경 사유가 필요합니다. 저장 차수가 맞지 않는 오래된 화면은 수정을 거부합니다. 변경 이력에서 당시 전체 입력값과 PDF를 확인할 수 있습니다.

당사자·원본 PDF·원계약은 저장 후 덮어쓰지 않습니다. 변경계약 버튼으로 원계약에 연결된 새 계약을 등록하세요. 같은 PDF와 기간이 겹치는 계약은 안내하지만 차단하지 않습니다. 변경계약 등록이 원계약을 자동 해지하지는 않습니다. 해지일과 기간은 실제 문서를 근거로 관리하세요.

회원사 명칭 변경·탈퇴·명부 삭제 후에도 체결 당시의 이름·번호와 수정 이력은 보존됩니다. 명부에서 삭제된 당사자는 그 사실을 표시합니다.

왼쪽 녹색 영역은 작업 화면의 전체 높이까지 이어집니다. 메뉴 조작 영역은 스크롤 중에도 화면에 유지되며, 작은 화면에서는 기존처럼 위쪽 메뉴로 표시됩니다.

## 데이터베이스·백업

마이그레이션 `0005`가 다음 테이블을 추가합니다. 기존 데이터와 계산 테이블은 변경하지 않습니다.

계약 연도·기간 구분은 기존 계약 JSON에 호환 가능한 필드로 저장합니다. 기존 계약은 시작 연도와 **기간 지정**으로 조회하며 원본 및 과거 이력을 일괄 수정하지 않습니다.

| 테이블 | 내용 |
| --- | --- |
| member_contracts | 최신 입력값, 당사자 참조·체결 당시 정보, 원본 PDF·원계약 연결, 수정 차수 |
| member_contract_documents | PDF 바이트, 파일명·해시·등록일·쪽수, 미확정 추출 후보와 텍스트 |
| member_contract_versions | 차수별 전체 스냅샷, 변경일시·사유·사용자 |

프로그램 설정의 기존 DB 백업에 세 테이블과 PDF가 모두 포함됩니다. 복원은 프로그램 종료 후 백업을 새 경로에 복사하고 `--db`로 열어 확인하는 기존 방식을 사용합니다. 원본 파일을 별도 폴더에서 수동으로 옮길 필요는 없습니다.

## 빌드와 검증

웹 빌드: `npm run build`

개발 실행: `./run.ps1 -Preview -Database build/contracts-preview.db -Port 18790` (새 테스트 DB 경로를 사용)

서버 검증: 프로젝트 의존성이 있는 Python에서 `python -m pytest tests/test_member_contracts.py -q`

브라우저 검증은 운영 DB에 실행하면 안 됩니다. `EPMS_TEST_URL`로 전용 서버 주소를 지정하고 `EPMS_CONTRACT_E2E=1`일 때만 `npx playwright test tests/browser/member-contracts.spec.ts --workers=1`로 실행합니다. 테스트는 기존 품목이 있는 DB에 예시 데이터를 넣지 않도록 거부합니다. 새 DB로 시작해야 재실행할 수 있습니다.

웹 빌드 결과는 `dist`에 생성됩니다. 기존 배포 EXE/ZIP에는 자동 반영되지 않으며 별도 패키징이 필요합니다.
