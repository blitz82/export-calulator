# PHASE 6 복수 품목란과 데이터 무결성

## 추출 및 원장 처리

- 신고번호, 품목란 번호, 정정 버전은 각각 별도의 식별 정보다. OCR에서는 품목란 번호의 선행 0을 저장하고, 승인 시 중복 판정은 기존 원장의 식별 규칙을 따른다.
- 동일한 신고번호와 정정 버전이 확인된 연속 을지에서 유일하게 대응하는 란번호를 보완한다. 품목란이 일치해도 기존 값이 다르면 각각의 후보를 유지하고 확인 안내를 표시한다. 새 갑지, 다른 신고번호·서식 단계·버전, 첨부 서류는 연결을 끊는다. 정정 표시는 보이지만 버전을 확인할 수 없는 페이지는 연결하지 않는다.
- 을지에서 값을 보완하면 필드의 근거 페이지를 기록한다. 원장 접수 기준 쪽은 기존대로 유지하고, 검토 중 필드 강조와 영역 재인식은 해당 필드의 실제 근거 쪽을 사용한다.
- 문서 총중량과 USD로 표시된 총신고가격은 개별 순중량과 품목 FOB와 별도로 표시한다. 합계 문자가 품목의 값을 덮어쓰는 경로는 없다. 서로 다른 의미의 중량을 대사하지 않으며, 문서 합계 일치 여부를 강제하지 않는다.
- 하나의 승인 요청에 동일한 활성 신고번호·품목란·정정 버전이 반복되면 등록 전에 오류를 반환한다. 기존 원장에 이미 등록된 자료 및 정정본의 중복 판정, 직접·간접수출 산정, 정책 기준일은 기존 규칙을 사용한다.

## 검증

| 사례 | 결과 |
| --- | --- |
| 합성 갑지·을지 | 품목란 001·002를 각각 유지하고, 을지에서 보완한 중량은 2쪽 근거를 가리킴. 총중량과 총 FOB는 별도 정보로 보존 |
| 새 갑지, 다른 신고번호·정정 버전, 중간 첨부, 숫자 충돌 | 별도의 품목 후보 유지 |
| 전자 PDF 14쪽 | 1개 신고번호 유지. 이어지는 쪽의 중복 후보를 정리해 17개에서 13개로 감소 |
| 전자 PDF 12쪽 | 3개 신고번호를 구분. 반복 후보 6개에서 3개로 감소 |
| 실제 스캔 혼합 PDF 4쪽 | 임시 PowerShell 세션에서 Windows OCR로 신고필증 2쪽을 구분. 항공화물운송장과 송장에는 신고 후보가 없음 |
| 승인 API | `1`과 `001`이 같은 활성 품목일 때 같은 버전의 중복 승인 요청을 거절. 실패 시 기존 원장 행 수를 유지 |

실제 업무 자료의 정정본 정확일치율은 독립 정답셋으로 검증해야 한다. 신고번호나 란번호가 누락된 페이지는 자동 연결하지 않는다. 이 증분은 배포용 패키징 없이 소스와 테스트 환경에서 검증했다.
