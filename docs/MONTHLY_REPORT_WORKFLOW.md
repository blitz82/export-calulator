# 월별 정산·지급보고

## 작업 순서

1. 공동선별비 정산에서 선별기록과 신고 품목란을 연결하고 계산을 확정합니다.
2. `월별 정산·지급보고`에서 새 보고서를 만들고 사업연도·보고월·대상 기간·지역본부·작성자를 입력합니다. 선별월·신고월·지급월은 서로 다를 수 있습니다. 날짜만으로 계산을 자동 편입하지 않습니다.
3. 확정 계산을 선택합니다. 일부 보고라면 회원사별 이번 금액·물량과 배분 사유를 입력합니다. 여러 회원사가 포함된 과거 계산에 귀속액이 없으면 원 계산액과 합계가 일치하는 회원사별 귀속액도 확인합니다.
4. 회원사별 내부결정액·검토일·검토자와 근거 PDF를 입력합니다. 계산액과 다른 경우 이유를 작성합니다. 시스템의 입력은 기존 내부 결재문서를 대체하지 않습니다.
5. 지출결의번호·결의일·문서 총액·이번 사업 대상 결의액을 입력하고 회원사별로 배분합니다. 문서 한 건에 여러 회원사를 연결할 수 있습니다.
6. 실제 지급·반환의 고유 거래번호·일자·수취인·금액과 증빙을 연결하고 회원사별 이번 보고 배분액을 입력합니다. 회원사와 실제 수취인이 다르면 근거 사유가 필요합니다. 지급 기록은 실제 은행 송금을 실행하지 않습니다.
7. 증빙·차이 점검에서 신고필증 원본 누락을 보완하고 개인정보와 참고 계산 포함 여부를 확인합니다. 가림 처리가 필요하면 제출 가능한 사본을 준비해 연결합니다. 이 기능은 자동 마스킹을 수행하지 않습니다.
8. 저장·점검 후 제출본을 생성합니다. 통합 PDF와 원본 증빙 ZIP을 다운로드하고, 실제 제출한 뒤 제출일·방법·접수번호·접수 증빙을 별도로 기록합니다. 파일 다운로드는 제출 또는 aT 승인으로 처리되지 않습니다.

## 금액·중복 점검

- 지원 계산액, 내부결정액, 지출결의액, 순지급액을 별도 보존합니다. 순지급액은 지급 합계에서 반환 합계를 뺀 값입니다.
- 계산·결정·결의 차이는 차이 사유, 결의 대비 미지급은 미지급 사유를 요구합니다. 초과 결정·초과 지급은 사유를 입력해도 제출본 생성이 차단됩니다.
- 실제 지급 증빙은 선별 작업자의 급여·작업비 지급 증빙과 구분합니다.
- 이미 보고한 계산 금액·물량, 같은 결의·지급 거래에 배분한 금액을 서버 트랜잭션에서 재검증합니다. 거래번호는 통합조직 내 고유하게 입력합니다. 은행별 번호가 겹치면 은행을 포함한 고유 번호로 구분합니다.
- 여러 보고서에 같은 거래를 배분할 수 있으나 거래 총액을 넘길 수 없습니다. 임의로 다른 번호를 붙인 동일 거래까지 자동 식별하는 기능은 아니므로 원문 대조가 필요합니다.
- 과거 지급의 반환은 해당 보고의 정정본에 원 지급과 함께 기록합니다. 과거 지급을 제외하고 반환만 별개의 새 보고에 넣어 음수 지급을 만들지 않습니다.
- 보고 기능은 기존 물량 잔량과 지원예산 사용액을 추가로 차감하지 않습니다. 실제 집행액 차이로 배정 예산을 변경하려면 기존 지원기준·배정 업무에서 별도로 검토합니다.

## 제출본·정정

제출본은 계산 당시 데이터, 기준 버전, 회원사명·사업자번호, 증빙 식별정보와 PDF·ZIP을 DB에 보존합니다. 백업 DB에 모두 포함됩니다. 동일 원본은 해시로 합쳐 부록에 한 번 첨부하며, 색인과 PDF 책갈피·원문 바로가기에서 관련 쪽으로 이동합니다. 원본 바이트는 ZIP에 보존합니다. 통합 PDF는 원본 전자서명의 효력을 대체하지 않는 열람용 사본입니다.

보존된 제출본은 직접 수정하지 않고 `정정본 작성`으로 이어갑니다. 정정본 생성 시 이전 점유를 교체하고 이전 PDF는 계속 다운로드할 수 있습니다. 원 계산 변경이 필요하면 `사유 기록·잠금 해제` 후 정산을 보완하고 정정본에서 최신 확정을 다시 선택합니다. 잠금 해제한 제출본은 다시 제출 상태로 바꾸지 않고 정정본으로 이어갑니다.

## 범위와 실행

통합 PDF는 범용 제출 자료이며 aT 공식 지정 서식을 자동 충족하거나 실제 접수·승인을 확인하는 기능은 아닙니다. 해당 연도 지침과 관할 지역본부 요청에 맞춰 제목·대상 기간·증빙을 확인하세요.

원본 합계 150MB·2500쪽까지 통합하며, 초과 시 보고 범위를 나눕니다. 암호화·손상된 PDF는 파일명을 안내하고 생성을 차단합니다. 원본 서명·개인정보·이체 증빙의 정확성은 사무국이 대조해야 합니다.

소스 실행: EPMS_SORTING_ENABLED=1을 설정하고 `launch.py --no-browser --port <포트> --db <DB>`.
웹 빌드: `npm run build`. Windows Lite 패키징: `package.ps1 -Python <Python 경로> -Lite -OutputRoot <새 출력경로>`.
마이그레이션 0009는 월별 보고·제출본·중복 점검 테이블 4개를 추가합니다. 기존 운영 데이터를 예시 데이터로 변경하지 않습니다.
