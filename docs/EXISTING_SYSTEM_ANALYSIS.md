# 기존 EPMS와 OCR 개발 범위

확인일 2026-11-17. 작업 폴더에 Git 메타데이터가 없어 브랜치, 변경 이력, 샘플 추적 이력은 확인할 수 없었다. 로컬 배포 폴더에서 v1.2.1 Lite 및 Portable ZIP을 확인했다. 소스 버전과 해당 ZIP의 일치는 확인하지 않았다. 기존 배포본과 분리된 경로에서 검증 빌드를 생성했다.

FastAPI의 기관별 OCR 경로는 PDF 및 페이지별 원본 추출 결과를 SQLite에 접수하고, 승인 요청에서 현행 신고원장 검증을 거쳐 등록한다. 검토 UI는 업로드, 원본 쪽 이동, 금액·순중량 원본 확인을 지원한다. PyInstaller는 정적 프런트엔드, 공식 서식 사본, PDFium, PowerShell OCR 스크립트를 수집한다. Portable은 고정 WebView2 런타임을 별도로 동봉한다.

| 현행 동작 | 샘플 또는 코드에서 확인된 영향 | 반영한 변경 |
| --- | --- | --- |
| Windows OCR 스크립트가 줄 문자만 반환 | 위치 강조와 국소 재인식에 쓸 단어 사각형이 없음 | WinRT 단어와 픽셀 사각형, 이미지 크기, 텍스트 각도를 JSON으로 수신 |
| 신고번호 값이 라벨 바로 뒤에 있다고 가정 | 갑지의 라벨 행과 다음 값 행에서 신고번호 추출 누락 | 상단 라벨과 아래 값을 정규화 위치로 연결 |
| 일반 품목란 정규식에 의존 | 실제 란번호/총란수 표시와 반복 품목 블록 추출 누락 | 품목 표제를 경계로 분리하고 총계 표제에서 개별 품목 추출 종료 |
| 신고번호 또는 품목란 중 하나만 나오면 보완하지 않음 | 금액·순중량·HS코드 누락이 남음 | 핵심 필드 누락 시 OCR을 시도하고 동일한 신고번호·품목란을 기준으로 보완 |
| 검토 초기값이 번호를 인식한 행 위주로 구성됨 | 부분 결과를 확인하기 어려움 | 원본에서 얻은 값이 있는 행을 유지하고 번호 미인식을 표시 |
| 승인 전 OCR 결과가 접수 JSON에 보존됨 | 동일 파일 재업로드 시 기존 추출 결과가 다시 표시됨 | 이전 형식의 미승인 파일을 다시 분석하고 기존 페이지 레코드에 저장 |

기존 회귀시험은 작업 전 47건 통과했다. 개발 시험은 별도 SQLite 파일에서 실행했다. SQLite 스키마 변경이 없으므로 신규 마이그레이션은 추가하지 않았다. 운영 DB의 위치와 실제 운영 자료를 사용한 검증은 범위에서 제외했다.
