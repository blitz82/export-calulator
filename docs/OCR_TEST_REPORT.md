# EPMS Smart OCR 검증 기록

시험일 2026-11-17. 기존 운영 DB와 배포본에 대한 쓰기 작업은 없었다. 별도 SQLite 파일과 합성 문서로 검증했다.

| 시험 | 실행 결과 |
| --- | --- |
| 개발 전 Python 회귀 | 47건 통과 |
| 개발 후 Python 회귀 | 51건 통과. 두 품목과 신고 전체 합계 분리, 후보 충돌 보존, 좌표 정규화, 이전 미승인 접수의 재추출을 포함 |
| Vitest | 2건 통과 |
| Playwright 및 Microsoft Edge | 7건 통과. OCR 검토 테스트에서는 API 응답을 모의하고 위치 강조, 충돌 후보, 재인식 후보 표시, 기존값 보존과 미확인 상태의 승인 차단을 확인 |
| 프런트엔드 타입 검사 및 Vite 빌드 | 성공. 기존 번들의 청크 크기와 일부 의존성의 모듈 지시문 경고가 출력됨 |
| 합성 전자 PDF | 실제 PDFium 경로로 신고번호, 신고일자, 란번호, HS, kg, USD를 추출하고 여섯 필드의 원본 좌표 및 PNG 미리보기 확인 |
| Windows 스캔 OCR | 스캔 파일 2개와 합성 이미지로 시도. 이 호스트의 Windows PowerShell 실행 정책이 스크립트를 차단함. 기존 호출 옵션의 실행 정책 우회는 제거 |
| SQLite 호환성 | 기존 접수 형식에서 같은 파일 및 페이지 ID를 유지한 채 추출 JSON을 갱신하고 승인 전 원장이 비어 있음을 확인. 운영 DB 사본을 이용한 별도 인수시험은 남아 있음 |
| Windows x64 Lite 및 Portable 검증 빌드 | 두 EXE를 `--no-browser`로 실제 실행하고 합성 PDF 업로드, 여섯 필드의 값·위치, 품목 FOB 좌표, 원본 미리보기, 오픈소스 정보 페이지와 승인 전 원장 미반영을 확인 |
| 최종 검증 ZIP | 두 ZIP의 무결성, SHA-256, SBOM의 파일 해시, 라이선스 페이지, 안내문, OCR 리소스, Portable 런타임을 확인. PDF와 DB는 없었으며 Excel 파일은 패키징용 공식 빈 양식 1개 |

정확도 목표는 [샘플 분석 보고서](OCR_SAMPLE_ANALYSIS.md)의 집계와 별개다. 현재 검증은 전자 PDF 파서 및 UI 동작에 집중했다. 실제 문서의 독립 정답셋, 스캔 OCR 실행 가능 환경, 회전한 페이지의 위치 변환과 다양한 정정 양식 인수시험이 남아 있다.

패키지에 대한 Windows 네이티브 WebView2 창, Python·Node.js 미설치 PC, 네트워크 단절 PC 및 실제 운영 DB 호환성 인수시험은 실행하지 않았다. [오픈소스 구성요소 관리](OPEN_SOURCE_COMPLIANCE.md)의 잔여 검토가 있어 검증 ZIP은 배포 준비완료 상태가 아니다.
