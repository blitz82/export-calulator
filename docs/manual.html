공동정산 수출실적 관리 안내

사용자관리자업무규칙 감사개발자검증 코드

사용자 매뉴얼

  1. 설정에서 통합조직과 연도별 계산 정책을 등록합니다.
  2. 회원사 관리에서 명부를 저장하고 신고 원장에 실제 품목란과 역할을 입력합니다.
  3. 계산 후 오류와 확인 필요 항목을 검토하고 원장을 수정한 뒤 다시 실행합니다.
  4. 회원사별 집계와 신고 품목란을 대사합니다. 공식 제출 메뉴에서 두 연도를 선택합니다.

관리자 매뉴얼

공동정산 수출실적 관리.exe와 같은 폴더의 내부 리소스를 함께 보관합니다. 설정에서 백업을 다운로드합니다. 복원 검증은 프로그램 종료 후 새 DB 경로로 복사한 백업을 PowerShell에서 & ".\공동정산 수출실적 관리.exe" --db "복원경로"로 엽니다.

정책은 확인 근거를 기록한 뒤 저장합니다. 공식 양식의 회원 기준일은 2026-12-31입니다.

업무규칙

기준일 회원사의 대행자·화주 역할은 직접수출, 제조자 역할은 간접수출입니다. 한 품목란에서 두 자격을 겸하면 직접만 한 번 귀속합니다. 서로 다른 회원사는 각각 인정합니다. 신고 품목란의 실수출액은 같은 자료가 반복 제출되어도 한 번 집계합니다.

감사 검증

실행번호를 선택하고 회원사 집계에서 신고 건을 엽니다. 실제 품목란, 자격과 인정 근거, 원본 파일명·시트·행과 변경 이력을 대조합니다. 감사증빙 ZIP에서 계산 검증 Excel 및 정책을 확인할 수 있습니다.

개발자 안내

FastAPI가 React 번들을 제공합니다. SQLAlchemy가 SQLite를 사용하며 Alembic이 초기 스키마를 관리합니다. npm run build, python -m pytest, npm run test:e2e를 실행할 수 있습니다. 개발 환경의 Windows 패키지 빌드는 package.ps1을 사용합니다.

검증 코드

M005는 동일 통합조직 내 중복 사업자번호입니다. D012는 동일 신고 품목란의 값 충돌입니다. D047은 역할 사업자 미확정, D081은 원본 파일 재가져오기, D083은 정정 전후 충돌입니다. 화면의 입력 항목에서 검증 코드와 보완 방법을 확인할 수 있습니다.
