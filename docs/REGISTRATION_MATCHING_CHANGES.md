# 등록·매칭 개선 결과 (2026-11-28)

## 1. 선별장 목록 및 종료일

`web/facility-registry.tsx`를 목록 우선, 검색, 20건 페이지, 신규 등록, 상세·수정 구조로 변경했다. 기존 변경 이력·수정 차수 검증은 유지했다. `web/sorting-facility-review.tsx`에서도 종료일을 선택 입력한다.

`epms/sorting_shared_api.py`, `epms/sorting.py`, `epms/settlement.py`에서 종료일 미입력을 null로 저장하고 열린 기간의 중복·기간 검사를 처리한다. 종료일이 있는 경우 날짜 역전과 기존 참조 검증은 유지한다. 시설 정보는 기존 JSON에 저장되므로 DB 테이블 마이그레이션이나 기존 데이터 일괄 수정은 없다.

## 2. 월을 넘는 선별매칭과 날짜

`web/settlement-board-model.ts`, `web/settlement-graph.tsx`의 신고 후보는 선별 기간 필터의 종료일에 묶이지 않는다. 생산자·잔량·신고 검증 조건을 유지하고 실제 선적일이 선별 시작일 이후인 자료를 제안한다. 수동 연결에도 날짜 검사를 적용한다. 동일 생산자의 복수 선별기록은 가능한 기록이 하나라도 있으면 후보로 노출한다.

`epms/settlement.py`에서 선적일 누락과 선별일 이전 선적은 사유와 관계없이 확정을 막는다. 기존에는 신고일 대체와 기간 사유로 역전 연결을 통과시킬 여지가 있었다. 다음 달 및 12월→다음 해 1월 연결 자체에 예외 사유를 요구하지 않는다. 선별기록 자체가 작업 대상 기간을 벗어나는 기존 검사는 유지한다. `epms/settlement_api.py`의 후보 날짜는 원장 날짜를 ISO 날짜로 읽어 제공하며 원본을 수정하지 않는다.

월별 집계는 기존 모델의 시작일을 날짜 기준으로 사용한다. 실제 날짜별 물량 구분은 담당자가 원문에 근거해 일별 기록으로 입력해야 한다. 초안 저장은 물량을 예약하지 않으며 실제 잔량 사용·확정 시 서버가 재검증한다.

## 3. 금액·중량 숫자 입력

`web/number-input.tsx`에 문자열 기반 공통 입력을 추가했다. 신고 원장·OCR 수동 보완·선별물량·정산 연결량·비용·지급액·지원 예산·회원사 배정·월별 보고액 등에 적용했다. 쉼표는 표시만 하고 상태에는 정규화한 문자열을 전달한다. 소수 끝의 0, 큰 수 정밀도, 빈 값과 0을 보존하며 중간 입력 시 커서를 복원한다. 서버의 기존 부호·범위·정밀도 규칙을 유지한다.

## 4. 확정차단 누락 원인·수정

`epms/contract_gate.py`의 기존 분기는 제조자 이름·역할·회원 정보가 미대조이면 계약 문제 없이 빈 결과를 반환했다. 일반 입력 오류가 별도로 차단하더라도 계약 차단 배너는 D090/D092만 확인하여 계약 관계를 검증할 수 없다는 사실이 누락될 수 있었다.

이 분기는 D091과 명확한 확정 차단 안내를 반환한다. `web/grid.tsx`에서도 동일 코드를 계약 차단으로 표시한다. 기존 공통 검증을 사용하는 개별·일괄 등록, Excel 가져오기, 현재 원장 재검증, 계산·최종 확정에 적용된다. 제조자 미대조인 Excel 입력을 실제 XLSX 요청으로 재현해 원장 임시 저장과 needs_review·D091 표시를 확인했다. 정상 계약·자기 수출·제외 행의 기존 정책은 유지한다. 과거 확정본은 수정하지 않았다.

## 5. 최소 입력·PDF 수동 확인

`web/sorting-intake-rows.tsx`의 기본 흐름은 생산자·선별일(기간)·수출용 물량·단위·PDF 연결이다. 시설·조직·품목은 기존 접수/조직 정보에서 연결하며 제목·원본번호는 자동 생성한다. 총량·내수·탈락·감모·메모는 선택 입력이다. 항목별 근거 문구와 OCR 실행은 등록 조건이 아니다. PDF 확인·기록 저장이라는 명시적 동작으로 기존 원문 확인 상태를 보존한다. 미완성 기록은 임시 저장할 수 있다.

`web/sorting-intake.tsx`의 OCR 보조는 접힌 선택 기능이다. `web/settlement-records.tsx`는 선별 입력에서 문서 연결 중심 안내를 제공한다. PDF 바이트·기존 근거 페이지·항목별 근거·과거 기록은 삭제하지 않는다. 현재 로컬 앱의 조직 범위·세션 검증을 유지했다. 별도 역할 권한 체계를 새로 만들지 않았다.

### 실제 증빙 확인 범위

sample2의 나주배원협·수곡덕천·탐진들 폴더에서 대표 PDF를 로컬 이미지로 렌더링해 확인했다. 탐진들 선별현황은 규격별 상자 수 및 중량 환산 정보가 있는 작업표이며, 다른 대표 자료에는 월별 집계·작업일지·수출실적표가 혼재한다. 일부 파일은 보관 폴더명과 본문 단체명이 달라 폴더명만으로 생산자를 자동 확정하지 않는다. 상자 수를 kg으로 임의 전환하거나 월별 수출실적을 일별 선별물량으로 자동 간주하지 않는다.

세 조직의 모든 페이지에 같은 필드가 있다는 전수 검증은 수행하지 않았다. 최소 입력은 실제 매칭 코드의 필수 정보에 근거하며, 문서에서 직접 확인할 수 없는 값은 추정하지 않고 임시 저장·보완한다. 대표 렌더 이미지는 개인정보가 포함될 수 있어 `output/sorting-private/manual-review`에만 둔다.

## 6. 등록 실패 안내

`web/sorting-intake-model.ts`에서 누락 항목을 필드명으로 반환한다. 저장 시 필드별 오류·행 오류 요약과 첫 오류 포커스를 제공한다. 날짜 역전·수출용 물량 형식·PDF 미선택·수정 사유를 구분한다. 저장 버튼을 필수값 때문에 숨기듯 비활성화하지 않는다. API 실패 시 입력·PDF 연결을 유지하고 저장 성공 시 오류 표시를 정리한다. 기존 서버 검증의 구체적인 오류 메시지도 행에 표시한다.
